# Nexus 工程连接器 Windows 使用说明

适用版本：**0.1.0**；文档日期：**2026-10-19**。本文面向从 Gitee 下载桌面发行包的 Windows 用户，首次操作可先看 [快速开始](快速开始.md)。

连接器在当前 Windows 用户会话中运行，从 Nexus 主动领取工程任务，通过本机受控桥接调用嘉立创 EDA 专业版的 CLI/API，再回传私有产物。电脑无需为连接器开放入站端口。

首次使用须在目标 Windows / EDA 环境完成连接检查和所需任务验证。连接检查通过不能代替完整任务验证或工程审查。

## 1. 电脑与服务端准备

### 1.1 用户电脑

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 22H2 / Windows 11，x64 |
| 桌面运行环境 | .NET Framework 4.8；按单位软件管理方式或 Microsoft 官方渠道安装 |
| Node.js | 此桌面发行包捆绑 24.21.0，无需安装系统 Node 或 npm |
| 编辑器 | 另行安装嘉立创 EDA 专业版；选择其实际 EXE，标准版不能替代 |
| Windows 账号 | 使用有权访问配置、工程目录的普通用户；应用不要求管理员权限 |
| 网络 | 能访问管理员指定的 Nexus HTTP/HTTPS 地址；首次 3D 导出可能还需要访问嘉立创模型库 |

先正常打开嘉立创 EDA 专业版，完成其首次初始化和所需登录，确认编辑器本身可用。桌面包不包含 EDA，也不替用户安装或升级 EDA。

### 1.2 Nexus 管理员须确认的条件

普通用户无需编辑服务器配置。若网页没有工程入口、无法配对或无法创建任务，请让管理员核对：

| 条件 | 核对内容 |
| --- | --- |
| 前端工程开关 | `VITE_APP_ENGINEERING_ENABLED=true`；前端配置变更需重新构建并部署才生效 |
| 后端工程开关 | `nexus.ai.engineering.enabled=true`；变更后重启对应后端，使工程接口装配生效 |
| 环境差异 | 当前仓库开发前端及后端 dev/local 已启用；生产仍须显式启用，不能由开发配置推断生产状态 |
| 私有存储 | `nexus.ai.engineering.oss-config-key` 指向专用、访问策略为 `PRIVATE` 的 OSS 配置；示例键 `engineering-private` 不代表环境中已创建该配置，不可回落到公共桶 |
| 用户权限 | `ai:engineering:device`、`ai:engineering:task`、`ai:engineering:query`、`ai:engineering:download`，分别用于设备配对管理、任务操作、查询及产物下载 |
| 工具开关 | 在工具管理中启用内置“嘉立创EDA工程工具”；仅能普通 AI 对话不代表已启用工程工具 |
| 代理与连接 | 工程 API 能通过指定地址到达对应后端，Redis 与 OSS 可用；多实例使用一致的 Redis 环境和部署版本 |

**后端必需更新：2026-10-19 Redis `global` 配对键修复。** 网页在已登录租户上下文生成配对码，连接器兑换时尚未获得租户身份，两端必须使用一致的全局配对摘要键；码内的租户和用户归属仍受校验，上传票据仍保持租户隔离。管理员须将修复部署到处理请求的**全部后端实例**并完成重启，再让用户生成新码。混用新旧实例仍可能失败；此前生成的码不迁移，应放弃并重新生成。**仅替换 Windows 客户端不能解决后端键不一致。**

本次 Windows 发行与上述配对键修复**无需 SQL 迁移**。已有工程功能所需的数据结构、菜单和权限由管理员核对环境基线；安装、升级或排查客户端时不要导入主初始化 SQL。

## 2. 从 Gitee 下载、校验与解压

### 2.1 选择同一发行版的文件

从 [Nexus-ERP Gitee 仓库](https://gitee.com/NexusERP/nexus-erp) 的 [工程连接器 0.1.0 发行版](https://gitee.com/NexusERP/nexus-erp/releases/tag/engineering-connector-v0.1.0) 下载 **Windows x64 桌面包**，发行标签为 `engineering-connector-v0.1.0`。不要把仓库源码 ZIP 或仅含 CLI 的包当作双击桌面应用。

下载以下两个同版文件：

- `nexus-engineering-connector-0.1.0-win-x64-desktop.zip`：完整桌面程序，内置 `快速开始.md` 和 `使用说明.md`。
- `nexus-engineering-connector-0.1.0-win-x64-desktop.zip.sha256`：该 ZIP 的 SHA-256 摘要。

Gitee 发行页也提供同版 `快速开始.md` 和 `使用说明.md` 的独立附件，便于下载前阅读或单独查阅。ZIP 中已包含两份说明，完整解压后即可通过文档链接互相跳转。

### 2.2 在 Windows 核对 SHA-256

将 ZIP 和 `.sha256` 放在同一下载目录，在该目录打开 PowerShell，执行：

```powershell
Get-FileHash -LiteralPath '.\nexus-engineering-connector-0.1.0-win-x64-desktop.zip' -Algorithm SHA256
Get-Content -LiteralPath '.\nexus-engineering-connector-0.1.0-win-x64-desktop.zip.sha256'
```

第一条命令输出的 `Hash` 应与第二条输出开头的 64 位十六进制摘要一致，大小写不影响比较。摘要不一致时停止运行，重新从维护者确认的发行版下载或联系维护者。校验值必须对应实际下载的 ZIP，请使用同一发行版随附的校验文件，不要与其他版本的摘要混用。SHA-256 用于核对文件完整性，仍须确认发布来源。

### 2.3 完整解压并保留目录结构

将整个 ZIP 解压到固定、当前用户可读的目录，例如 `C:\Apps\NexusEngineeringConnector`。程序旁的关键内容包括：

| 文件或目录 | 用途 |
| --- | --- |
| `NexusEngineeringConnector.exe` | 双击启动的桌面应用 |
| `NexusEngineeringConnector.exe.config` | .NET 运行配置 |
| `runtime` | 捆绑的 Node、运行版本信息及许可证 |
| `dist`、`node_modules` | 连接器与所需依赖 |
| `templates` | 受控工程模板 |
| `scripts` | 随包凭证保护等固定脚本 |
| `distribution-manifest.json` | 打包内容的逐文件大小和 SHA-256 清单 |
| `快速开始.md` | ZIP 内置的首次操作指引 |
| `使用说明.md` | ZIP 内置的完整使用说明，两份文档通过相对链接互相跳转 |

不要在压缩包预览中启动，不要只复制 EXE，也不要拆开或随意替换 `runtime`、脚本和依赖文件。缺少文件时重新完整解压同版发行包。

### 2.4 未数字签名与 SmartScreen 提示

本版应用**尚未数字签名**，Windows 可能显示“Windows 已保护你的电脑”或“未知发布者”。这类提示本身不能证明文件可信。

1. 先核对 Gitee 仓库是否为维护者指定来源、版本及文件名是否正确、SHA-256 是否匹配。
2. 确认来源可信且符合单位软件策略后，可查看 SmartScreen 的“更多信息”，核对应用名称；只有界面提供该选项且单位策略允许时，再自行决定是否选择“仍要运行”。
3. 若来源或摘要无法确认、安全软件报告具体威胁，或单位策略阻止运行，应停止并联系维护者或管理员。

无需关闭 SmartScreen、Defender 或其他安全保护，也无需“以管理员身份运行”。缺少 .NET 时按正常软件安装流程处理，不通过提权绕过来源核查。

## 3. Nexus 服务地址怎么填

“Nexus 服务地址”接受 HTTP 或 HTTPS，可使用域名、局域网 IP 和带方括号的 IPv6。HTTP 直接可用，不需要勾选开发模式；跨不可信网络优先使用管理员提供的 HTTPS 地址。

| 场景 | 可填写的示例 | 说明 |
| --- | --- | --- |
| 站点根地址 | `http://nexuserp.website` | 自动识别根路径、`/prod-api`、`/dev-api` 中的工程 API |
| 显式生产 API | `http://nexuserp.website/prod-api` | 已知反向代理仅开放 `/prod-api` 时可直接填写 |
| HTTPS 站点 | `https://erp.example.com` | 示例域名，替换为管理员提供的实际地址 |
| 本机开发前端 | `http://localhost:80` 或 `http://localhost:80/dev-api` | 当前开发前端端口为 80，`/dev-api` 代理到 `http://localhost:8080` |
| 本机直连后端 | `http://localhost:8080` | 使用后端根地址，不额外拼 `/dev-api` 或 `/prod-api` |
| 局域网后端 | `http://192.168.1.20:8080` | 示例 IP，须替换为实际后端地址；也可使用内网域名 |
| IPv6 后端 | `http://[::1]:8080` | 本机 IPv6 示例；地址两侧保留 `[]`，跨机需实际可达的 IPv6 和监听配置 |

以上域名和地址用于说明填写方式，不代表对应站点已部署或当前可访问。`localhost` 和 `[::1]` 都指**运行连接器的这台电脑**；如果 Nexus 在另一台机器，须填写服务器的实际地址。当前后端本地配置默认只监听回环，跨机访问需管理员另行核对监听与网络配置。

填写站点根地址或 API 基地址即可，不要填写登录页、带任务编号的网页地址，也不要在地址中加入账号密码、查询参数、`#` 片段、浏览器 Token 或配对码。

发送配对码或设备身份前，连接器会对候选基地址的 `/ai/engineering/connector/pair` 发起**不带认证的 GET 只读探测**。根地址会依次尝试直连、`/prod-api`、`/dev-api`；显式填写这两个 API 前缀之一时只使用该地址。探测不兑换配对码，不修改业务数据，候选路径始终在同一站点，**任何重定向都不会跟随**。

若 HTTP 被跳转到 HTTPS、域名被跳转到其他域名，或 API 被跳转到登录页，请向管理员确认最终 API 地址并直接填写；不要依赖跳转完成配对。修改已绑定的服务地址，包括协议、域名、端口或 API 路径后，须重新配对，操作见第 7 节。

## 4. 首次配置、配对和启动

### 第一步：打开应用并保存设置

1. 双击解压目录中的 `NexusEngineeringConnector.exe`。若提示“连接器已运行”，请到任务栏通知区域查找其图标；图标可能在“显示隐藏的图标”中。
2. 填写“Nexus 服务地址”。
3. 点击“浏览…”，选择已安装的嘉立创 EDA 专业版 **EXE**，不要选择快捷方式、安装包、工程文件或连接器自身的 EXE。
4. 点击“保存设置”。配置保存在当前 Windows 用户目录，程序不会把用户配置写回发行目录。

### 第二步：检查本机 EDA

点击“检查 EDA”，等待右上角状态和“运行记录”的诊断结果。

- 显示“EDA 连接检查通过”且诊断 `connected=true`：本机编辑器连接检查通过，可以继续配对。
- 显示“EDA 尚未连接”或 `connected=false`：确认选择了正确的专业版 EXE，手动打开 EDA 并完成初始化后重试。EXE 文件存在不等于编辑器已连接。
- 显示“操作未完成”：依据运行记录中的具体诊断检查 EDA 版本与 CLI 能力。检查期间等候完成，不要重复点击。

诊断中的 `cliVersion`、`editorVersion` 和 `versionMatch` 来自实际返回；缺失或不匹配时应核实安装版本。本机“检查 EDA”不访问工程服务接口，不能证明 Nexus 工程开关、配对或 OSS 正常。

**如何理解 CLI 模式：** 当前连接器上报 `transportMode=CLI_COMPAT`，由自身的 STDIO MCP 桥接调用嘉立创官方 CLI/API。已有能力核对基线为嘉立创专业版 **4.1.60**：该版本原生 MCP 调用返回 `MCP_NOT_SUPPORTED`，诊断可能显示 `NATIVE_MCP_UNSUPPORTED`；此提示应结合 `connected` 和 CLI 检查结果判断，不能直接等同于 EDA 不可用，也不能据此宣称原生 MCP 可用。其他版本可能显示 `CLI_COMPAT_UNVERIFIED`，须在目标机器核对实际能力；无需另行开启 EDA 原生 MCP 端口。

### 第三步：在网页生成五分钟配对码

1. 在浏览器登录与应用地址对应的 Nexus 环境，并确认当前租户和账号是需要接收任务的归属。
2. 进入“工程设备”，点击“配对新设备”。网页会显示一次性配对码及有效期，**五分钟内**完成兑换。
3. 点击“复制配对码”。如果网页提示“剪贴板不可用”，在文本框中手动选中内容并按 `Ctrl+C`，再到桌面应用中粘贴；内网 HTTP 等环境中出现该情况时，仍可手动复制。
4. 在应用“一次性配对码”中粘贴完整内容，点击“配对设备”，等待“配对成功”。不要把码粘贴到服务地址，也不要用浏览器 Token 替代。

配对码只使用一次，提交后应用会清空输入框，码不写入配置或磁盘。已兑换、过期或配对结果不确定时，先刷新网页设备列表核对，再按需生成新码；不要反复使用旧码。设备归属于生成码的 Nexus 租户和用户。

### 第四步：启动并确认设备状态

1. 点击“启动连接器”。窗口会显示“连接器运行中”，程序开始认证、上报心跳并领取任务。
2. 在网页“工程设备”点击“刷新”，查看是否有本机设备、最近心跳是否更新。
3. 分别核对“状态”为在线、“编辑器连接”为已连接，以及“实际传输 / 诊断”、CLI 与编辑器版本、实际能力。

桌面“运行中”表示本次 Node 工作进程已经启动；网页“在线”表示设备有近期心跳，编辑器是否可用看独立的“编辑器连接”列。只有配对成功但未启动时，不应据此期待任务执行；服务端或 EDA 检查失败也不能由窗口状态代替。

完成首次配置和配对后，以同一 Windows 用户再次双击应用，会自动启动已有绑定。**这是打开应用后自动运行，不是注册 Windows 开机自启。** 可手动为 EXE 创建桌面快捷方式，目标保持为完整解压目录中的程序。

## 5. 在 Nexus 使用工程任务

1. 保持连接器运行，确认网页设备在线且编辑器已连接。
2. 打开 Nexus AI 对话，主动在“工程设备”下拉框选择自己的设备。若没有设备或工程工具入口，让管理员核对第 1 节的开关与权限。
3. 先发送连接检查请求，例如：“检查所选工程设备与嘉立创 EDA 的连接状态。”通过卡片“查看检查结果”核对实际 CLI、编辑器版本和传输模式。连接检查不会生成 PCB、BOM 或三维模型。
4. 需要生成草稿时再明确请求，例如：“基于温湿度模板生成 50×35mm 双层 PCB 草稿，并展示线路和 3D。”按页面提示确认后跟踪任务。
5. 从卡片“查看预览”或“工程任务”列表进入详情。工具调用结束只表示任务已派发；以任务详情的最终状态、错误说明和实际产物为准。网页刷新后可重新查询持久化结果。

当前“工程任务”列表路径为 `/ai/chat/engineering/task`，这是**浏览器页面路径**，不要将其作为连接器服务地址。

结果页可按实际产物查看 PNG、BOM、DRC、OBJ/MTL 及源文件；三维视图支持旋转、缩放、平移和重置。缺少模型或报告时按实际缺失显示，不能将“部分成功”理解为 DRC 通过。下载须具备 `ai:engineering:download` 权限，产物通过私有权限链路读取。

需要继续编辑时，在具备相应操作入口的任务卡片点击“打开本地工程”，该动作由对应设备执行；也可在应用中点击“打开工作目录”，找到任务的 `project` 目录并从嘉立创打开。派生的打开、导出与 DRC 操作依赖原设备和保留的本地工程。

**模板使用边界：** 当前温湿度演示模板支持 40–100mm × 30–100mm 的双层板框，只参数化板框，使用固定四个器件及初步走线；完整原理图、电源布线和电气审核尚未完成。真实 DRC 违规、未连接网络和未发布标识必须保留，须经工程师审查，不能直接投产。该流程不会替代 ERP BOM、采购或 MES 工单的业务审批。

## 6. 窗口、托盘、停止与断线

| 操作 | 实际行为 |
| --- | --- |
| 窗口右上角 `×` | 隐藏到系统托盘，连接器继续运行 |
| 双击托盘图标 / “打开窗口” | 恢复窗口 |
| 窗口“停止” / 托盘“停止连接器” | 请求停止本次工作进程，应用仍保留，可以再启动 |
| 托盘“退出应用” | 先停止工作进程，再完全退出应用 |
| 再次双击 EXE，提示已运行 | 同一 Windows 用户会话已有实例，从托盘打开原窗口即可 |

运行或检查过程中，设置和配对按钮会暂时禁用。需要更改设置时先“停止”，等待停止完成再操作。任务执行期间停止或取消只在可确认的步骤边界生效，不能保证撤销编辑器已执行的更改。

正常停止会通过控制通道请求取消；超过 **10 秒**尚未结束时，桌面应用会终止本次自身启动的 Node 工作进程并提示“已停止，需核对任务”。程序不会按进程名批量结束系统 Node，也不会强杀用户的 EDA 进程；自身创建的编辑器会话按任务逻辑管理，用户既有工程不因此被关闭。工程文件会保留。

每台设备串行执行任务。断网、停止兜底或租约状态不明确后，先到网页核对原任务，再检查本地工程。连接器不会自动重放执行状态不确定的设计写入；遇到 `EXECUTION_UNCERTAIN` 时，应由工程师确认已有文件后决定新建导出或重试任务，避免重复写工程。网页“取消”和本地“停止”也不能替代对已产生文件的核查。

## 7. 配置、身份、工程与换绑

### 7.1 当前用户目录

在资源管理器地址栏输入 `%LOCALAPPDATA%\Nexus\EngineeringConnector` 可直接打开用户数据根目录。程序目录与用户数据目录相互独立。

| 路径（相对上述根目录） | 内容与注意事项 |
| --- | --- |
| `config.json` | Nexus 服务地址、EDA EXE 路径和工作目录等配置，不包含一次性配对码 |
| `workspace\identity.dpapi` | Windows **DPAPI CurrentUser** 加密的设备身份，与当前 Windows 用户及 Nexus 地址绑定 |
| `workspace\tasks\<taskId>\<attempt>\project` | 各次任务保留的源工程；占位符由实际任务编号与尝试次数替换 |
| `workspace` 下其他运行文件 | 任务恢复、引用及产物等；可能包含受保护的运行信息，不应随意删除或公开 |

“打开工作目录”直接进入 `workspace`。本地身份不能通过复制到另一台电脑或另一个 Windows 用户来直接复用；更换电脑或账号时应备份工程，并在新环境重新配对。

备份和对外提交问题时，优先只选择需要的工程、导出文件与脱敏信息；不要把整个用户目录、`identity.dpapi`、恢复记录、配对码或设备凭证上传到 Gitee、工单附件或聊天中。

### 7.2 改地址、换账号或解除绑定

1. 先在网页核对正在执行的任务，再在应用中点击“停止”。
2. 旧服务仍可访问时，在**保留旧地址**的情况下点击“解除绑定”，确认并等待成功。网页也可对旧设备执行“解绑”，之后该设备不能继续回报或上传。
3. 修改“Nexus 服务地址”并“保存设置”。即使是同一站点从根地址改为 `/prod-api`，也应重新配对；旧身份不能当作新地址的通用凭证。
4. 在目标环境、目标租户和账号下重新生成配对码，配对后点击“启动连接器”。

如果旧服务不可达、旧绑定已失效或桌面解绑失败，联系管理员在旧环境撤销旧设备，再按目标环境重新配对。不要把一次失败的解绑当作服务端已撤销。解除绑定会保留源工程；只在网页退出登录也不会自动停止桌面连接器。

## 8. 常见故障与诊断码

先区分失败发生在**本机 EDA 检查、API 地址识别、配对、运行还是任务产物阶段**。记录受控错误码、发生时间、应用/EDA 版本和失败步骤即可，不需要提供完整响应、配置内容或当前诊断日志。

| 现象或诊断码 | 含义与处理 |
| --- | --- |
| `PAIRING_INVALID` | 码无效、已兑换或已过期。核对同一环境，在网页生成新码并于五分钟内兑换。若刚生成的新码立即失败，按下方专项顺序核对后端修复，不要只换客户端包 |
| `ENGINEERING_DISABLED` | 后端工程功能未启用或接口不存在。管理员核对实际运行环境的 `nexus.ai.engineering.enabled`、后端版本、代理路由，启用后重启对应实例 |
| `API_NOT_FOUND` / `INVALID_RESPONSE` | 当前地址返回网页或无效 JSON，未找到工程 API。核对是否应填 `/prod-api`、`/dev-api` 或后端直连地址，不要填网页菜单路径 |
| `API_UNREACHABLE` | 无法访问工程 API。核对地址、DNS、端口、服务器监听及网络；浏览器能打开登录页仍不代表 API 可达。HTTPS 证书有问题时由管理员修复，不要关闭证书校验 |
| `API_REDIRECTED` | API 返回重定向。连接器不会跟随任何跳转；向管理员确认最终 HTTP/HTTPS、域名及 API 地址，直接填写后重新配对 |
| `API_ADDRESS_INVALID` | 地址格式不符合要求。只填 HTTP/HTTPS 根地址或 API 基地址，移除账号密码、查询参数和片段，IPv6 使用方括号 |
| `API_ACCESS_DENIED` / HTTP 401、403 | API 或身份被拒绝。管理员核对反向代理、工程权限、账号/租户状态及设备绑定；不要尝试复制浏览器 Token |
| `API_UNAVAILABLE` / HTTP 5xx | 后端或代理暂时异常。管理员核对服务运行及同一时间的后端情况，恢复后再试 |
| `REQUEST_TIMEOUT` | 工程服务请求超时。核对网络与后端负载，回网页确认配对或任务是否已有结果后再重试 |
| `PROTOCOL_UNSUPPORTED` | 客户端与服务端协议不兼容。让管理员协调部署匹配版本的连接器与后端后重新核对，不能只修改配置中的协议字符串 |
| `DEVICE_REVOKED` / “本机绑定已失效” | 设备身份被撤销或不可用。核对账号、权限和服务地址，在目标环境重新配对 |
| “Windows 用户凭证保护失败” | 当前用户无法处理原身份。确认是否换过 Windows 用户或电脑；重新配对，不复制他人的身份文件 |
| “EDA 尚未连接” / `EDITOR_UNAVAILABLE` | 查看本机 EDA 是否正常打开，EXE 是否为专业版，CLI 与编辑器版本是否匹配；再次“检查 EDA” |
| `CLI_COMPAT` / `NATIVE_MCP_UNSUPPORTED` | 前者是实际 CLI 兼容模式，后者说明该基线版本的原生 MCP 不可用。结合 `connected` 和任务检查结论判断，勿当作原生 MCP 已启用 |
| `CLI_COMPAT_UNVERIFIED` | 当前版本不属于已核对的 CLI 基线，需在目标机器完成连接与实际任务能力核对 |
| `EXECUTION_UNCERTAIN` | 无法确认设计动作是否已完成。保留工程，核对原任务和编辑器中的文件，再决定新建导出或重试，不盲目重复生成 |
| “分发文件不完整” / 应用启动失败 | 重新完整解压同版 ZIP，核对 `runtime`、`dist`、依赖及 EXE 配置文件；确认 .NET 4.8 和用户目录可写 |
| 网页“复制配对码”不可用 | 手动选中文本并按 `Ctrl+C`，在应用中按 `Ctrl+V`；无需更改浏览器安全设置 |
| 设备在线但没有产物 | 确认编辑器已连接、已在 AI 对话选择设备并发起生成任务；连接检查本身没有工程产物。查看任务最终状态和缺失说明 |
| 上传失败或大文件被拒绝 | 由管理员核对专用私有 OSS、上传票据及代理/后端大小限制；客户端停止或失败后本地工程仍可保留，不能因应用运行中就判断上传完成 |

### 刚生成的新码也立即无效

1. 确认网页与连接器使用同一环境，核对 API 前缀，并刷新设备列表排除实际已配对但界面尚未更新的情况。
2. 让管理员确认已部署 **2026-10-19 Redis `global` 配对键修复**，并确认负载均衡后所有处理请求的后端实例均已统一更新、重启，使用一致的 Redis 环境。
3. 放弃更新前生成的码，待全部实例就绪后，在网页生成新的五分钟码并兑换。修复不迁移旧码，也不需要 SQL 迁移。
4. 仍失败时，仅向维护者提供版本、错误码、脱敏后的环境标识和发生时间，由管理员核查服务端；不要发送配对码、设备身份、Redis 负载或真实业务文件。

## 9. 升级、迁移与卸载

### 9.1 升级

1. 到 Nexus 核对活动任务，按需等待完成或请求取消，再到旧应用托盘选择“退出应用”，等其完全退出。只关闭窗口会留下托盘进程。
2. 按需备份各任务源工程和导出文件，妥善保管，不将运行身份作为公开备份。
3. 下载新版 ZIP 和相应 SHA-256，核对后**完整解压到新目录**，保留旧目录以便核查版本；不要覆盖仍在运行的文件或混用新旧依赖。
4. 以原 Windows 用户启动新版。程序会继续读取 `%LOCALAPPDATA%\Nexus\EngineeringConnector` 中的配置、身份和工程；同一服务地址、绑定有效且协议兼容时可继续使用。若服务地址变化或身份失效，重新配对。
5. 重新检查 EDA 与网页心跳，更新桌面快捷方式至新版 EXE，再按需删除已经退出的旧程序目录。

更换 Windows 用户或电脑时，只迁移需要的工程文件，在新环境重新选择 EDA、配置地址并配对。复制整个程序目录不会迁移用户身份，也不能代替目标机器验证。

### 9.2 卸载与保留工程

本版为解压即用，无安装卸载向导。停止使用时：

1. 先核对任务并停止；不再使用此设备时，保持旧地址执行“解除绑定”，或在 Nexus 网页“解绑”，确认服务端撤销成功。
2. 在托盘选择“退出应用”。
3. 删除完整解压的程序目录和自行创建的快捷方式即可。

**删除程序目录会保留** `%LOCALAPPDATA%\Nexus\EngineeringConnector` 下的配置、加密身份和源工程。若只想移除应用并保留工程，到此结束。确需清理用户数据时，应先备份所需工程并确认旧设备已解绑，再由用户自行处理；不要直接删除整个 `workspace`，否则保留的任务工程与恢复资料也会丢失。
