# 文生图独立菜单页实现计划

## Context

二阶段 S2-C 的文生图功能虽已实现后端 `TongYiWanxImageService`(通义万相 + OSS 持久化),但前端**没有独立入口**——仅靠智能对话页 auto 模式下的关键词路由触发,且关键词集(`画一个/画一张/生成图片` 等 7 个)覆盖太窄,用户正常输入"画一只猫"根本触发不了;同时 `ImageRenderer.vue` 组件写了但从未被任何文件引用(孤儿组件)。

用户要求:把文生图做成**独立的菜单页**(不在智能对话页显示),并**做持久化历史记录**,移除智能对话页原有的图片关键词自动路由。

预期结果:AI 智能助手目录下新增"文生图"菜单,页面含生成区(prompt + 尺寸 + 生成按钮 + 结果展示)和历史区(分页表格 + 缩略图 + 删除);智能对话页彻底不再触发文生图。

**generate 端点核心逻辑**(复用现有服务,不写新业务):

3. 构建 `ImageContext.builder().modelConfig(imageModel).prompt(req.getPrompt()).size(req.getSize()).build()`,调 `svc.generateImage(ctx)` 返回 OSS URL
4. 落库 `AiImageRecord`(userId/prompt/imageUrl/size/modelId/modelName),返回记录

**list 端点**:`startPage()` + `LambdaQueryWrapper` 按 `userId = getUserId()` 倒序查,返回 `TableDataInfo`。

## 二、前端

### 2.1 新建 API 封装

**`plus-ui/src/api/ai/image.ts`** 沿用 `market.ts` 模式:

```ts
import request from '@/utils/request';

export interface AiImageRecord {
  id?: number;
  prompt: string;
  imageUrl: string;
  size?: string;
  modelName?: string;
  createTime?: string;
}

export function generateImage(data: { prompt: string; size?: string }) {
  return request({ url: '/ai/image/generate', method: 'post', data });
}
export function listImage(query?: { pageNum?: number; pageSize?: number }) {
  return request({ url: '/ai/image/list', method: 'get', params: query });
}
export function delImage(ids: Array<number | string>) {
  return request({ url: `/ai/image/${ids}`, method: 'delete' });
}
```

## 六、注意事项

- **依赖前置**:文生图功能依赖 `modelType=IMAGE` 的默认模型已配置,否则 `generate` 端点抛 `ServiceException("未配置默认图像生成模型")`。前端生成按钮点击后若收到此错误,提示用户去模型管理页配置。
- **超时**:通义万相生成通常 10-30s,同步 REST 端点可能接近 axios 默认超时。前端 `generateImage` 调用需单独设 `timeout: 60000`;后端无超时问题(异步线程池不阻塞)。如运行时发现超时,后续可改为 SSE。
- **OSS 依赖**:图片持久化到 OSS 由 `TongYiWanxImageService.persistToOss` 处理,失败时兜底返回通义万相临时 URL(可能有时效,历史记录里的图片可能失效)。这是现有实现行为,本次不改动。
- **menu_id 1810 段**:经核查 `script/sql/ry-vue.sql` AI 模块菜单(1700-1804),1810-1813 未被占用,无冲突。
