## 八、关键技术建议

### 8.1 架构层面

| 建议 | 说明 |
|------|------|
| **统一审批引擎** | ~~以 R-003 `PuWorkflowService` 为模板，抽象出 `AbstractApprovalService`~~ Flowable 已直接嵌入各 Service，统一审批模式已形成 |
| **库存策略可配置化** | R-013/R-014 的上架/拣货策略应支持按仓库/物料类别配置不同策略（通过 `WmWarehouse` 或 `BdMaterialCategory` 上的配置字段） |
| **事件驱动解耦** | 采购收货→IQC→入库 这条链路建议用 Spring Event 或消息队列解耦，避免 Service 之间直接循环依赖 |

### 8.2 代码质量

| 建议 | 说明 |
|------|------|
| **异常处理规范化** | 当前大量使用 `throw new RuntimeException("...")`，建议统一为 `ServiceException` + 错误码 |
| **状态常量集中管理** | 各 ServiceImpl 中的 `STATUS_DRAFT`/`STATUS_CONFIRMED` 等字符串常量建议提取为枚举类，避免拼写错误 |
| **补充 Java 枚举** | `pu/domain/enum/` 目录为空，采购状态应建立 Java 枚举类，替代硬编码字符串 |
| ~~SQL 脚本完整性~~ | ~~采购行表 DDL 已补充到 `ry-erp.sql`~~ |

### 8.3 性能与可靠性

| 建议 | 说明 |
|------|------|
| **库存并发控制** | 库存过账操作应加乐观锁（version 字段）或分布式锁，防止并发扣减导致超卖 |
| **MRP 计算缓存** | MRP 净需求计算频繁查询库存，大数据量时建议加 Redis 缓存或批量查询优化 |
| **幂等性保证** | `generateWorkOrders()` 和 `convertToSalesOrder()` 等转单操作应增加幂等性保护 |

### 8.4 测试策略

| 建议 | 说明 |
|------|------|
| **状态机单测** | 工单/销售订单/采购订单的状态流转方法是核心业务逻辑，必须有完整单元测试覆盖所有合法/非法状态转换 |
| **库存过账集成测试** | 7种库存策略的过账操作需要有集成测试，验证库存主表和流水表的一致性 |
| **转单链路测试** | 报价→订单、申请→订单、订单→收货、订单→退货 等转单链路需要端到端测试 |
