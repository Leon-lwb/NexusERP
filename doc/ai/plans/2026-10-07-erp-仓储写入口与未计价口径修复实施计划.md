# 仓储写入口与未计价口径修复实施计划

> 记录日期：2026-10-07；基线 `b27f9aaacd02150dd681cb49ea4ee00b5125b05d`。
> 面向执行 Agent：使用 subagent-driven-development，按任务完成 RED→GREEN、规格审查、质量审查，再集成。

**目标：**修复上轮实际业务对账和源码核验发现的可用库存、PDA 批次、手工生产入库及未计价金额问题，不重做已完成业务或改写历史账。

**架构：**保留当前 Controller、权限、ERP 数据源和事务边界；生产入库以同租户原工单锁串行所有同源写入口，新增固定 SQL 来源守卫。库存候选及金额只修正真实读取/新编辑语义，不迁移旧行；PDA 只授权能够明确解析的物理库存身份。无新增表、签发平台或权限扩张。

**技术：**Java 21、Spring 事务、MyBatis-Plus/MySQL、Vue 3/TypeScript、JUnit/Mockito、现有原生 Node 前端用例。

## 设计取舍

1. 选择既有入口内最小修复，而非增加平行接口或靠 UI 避险。执行前锁定重读，拒绝来源冲突；未知不当零。
2. 生产入库维持现行自动完成的一工单一次终态数量语义，停止旧服务自称支持的累计补差额伪成功。已有完整已执行结果只返回原引用，金额/物料/数量/批次/仓位漂移失败；无完整凭据不能以 hasPosted 认定成功。
3. 草稿只能新建/编辑 DRAFT；普通请求不能设置 EXECUTING/EXECUTED、换工单或成品物料。删除先核全集，终态或有过账凭据全批拒绝。实际执行必须原工单 COMPLETED、真实待入库数量及有效单位/仓储。
4. PDA 已明确分配的批次和库位禁止扫码悄悄改身份；未绑定的扫码须唯一解析真实同租户物料/仓库/库位/批次，绑定 ID 与编码，并对该实际来源做 QC/效期/预留检查。
5. 参考金额与实际成本是不同事实：存在缺价/缺额时读端不可展示 0 或不完整合计；合法已知零价保留。不得用 TX 成本回填参考价、追认旧价格或修改已完成单据。

## 实际反例驱动的最小补充范围

- 审查实际复现：累计完成量包含审核报工，必须先减报工再对本次量核计划；合法零效果草稿删除不永久堵住工单，批次到期/锁定/关闭不抹除过去完整入库结果；恢复仍核真实物料根单位与库存物料编码。
- 原自动上层同时过滤明确零效果退休草稿，已存在完整结果经原 execute 的验证分支复核，不重新倒冲；CLOSED 只认原结果恢复，不能首次入库。
- 为使 ATP 与真实扣料一致，补生产领料策略查询及原子扣减的逻辑删除条件；清参考价使用明确请求动作，不把省略字段当清空指令。
- 全前端实际 type-check 暴露两个既有 TS1149：拣货/上架规则导入与 Git 跟踪 pickingRule/putawayRule 大小写不符。仅改两条 import，不改业务 URL、路由或关闭类型检查；4 项 Node 用例先 RED 再 GREEN。
