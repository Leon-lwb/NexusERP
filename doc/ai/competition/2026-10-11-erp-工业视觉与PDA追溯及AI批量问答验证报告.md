## 2. 工业缺陷检测

### 2.1 接口和页面

- 页面路由：`/erp/cv/defect`；接口：`POST /cv/detect/defect`；权限：`cv:detect:query`。
- multipart 文件字段仍为 `file`；`scenario` 仅允许 `defect_metal`、`defect_pcb`，本接口关闭 OCR。
- 检测框采用 Vision 返回的原图像素坐标，按显示尺寸等比例换算；页面展示缺陷类别、最高置信度、数量和本次推理耗时。
- 更换图片或场景后清空旧结果；上传错误和推理失败显示明确提示；真实零检测结果显示“本次模型未检出缺陷”。

联调发现并修复了快速切图问题：共享请求拦截器将 FormData 序列化为相同的 `{}`，500 ms 内不同图片的请求被误判为重复提交。仅为新检测 API 关闭该重复提交比较，保留页面请求中防重复点击机制。专项测试使用真实共享拦截器，验证快速切换可用且其他业务写入仍保留原拦截行为。

### 2.2 模型场景确认

Vision 原逻辑会在场景未注册时回退通用模型。工业页面不能将通用模型的零检测结果解释为工业模型结论，因此补充了以下契约：

1. Vision 成品检测增加可选 `strict_scenario`，默认 `false`，保持旧调用行为；严格模式在场景未注册时返回 `INVALID_SCENARIO`，权重缺失仍返回 503。
2. Vision 响应增加 `effective_scenario`，返回实际执行的模型场景。
3. ERP 工业调用发送严格模式并校验确认字段。字段缺失、回退 `general` 或确认其他模型场景均明确失败；旧版本服务忽略新请求参数也无法伪装为成功。
4. 旧双参数 OCR 调用不要求新增确认字段。请求的工业模型正常执行但没有检测项时，仍允许成功返回零条。

## 3. PDA 制造 SN 追溯

聚合服务位于 `ruoyi-admin`，使用现有 MES 与 ERP 服务，不增加 ERP 到 MES 的循环模块依赖。原仓储 `resolved.sn` 保留，制造 SN 单独返回 `resolved.manufacturingSn` 与 `mes.manufacturing`。

- 制造来源标记为 `MES_PRO_SN`，不把流转卡共同进度描述成每个 SN 都发生的过站记录。
- 工序进度展示流转卡记录；SN 过站履历展示当前 SN 的真实 Station 报工记录。
- 过程检验按当前流转卡或工单关联，排除其他流转卡的专属检验；页面显示检验关联范围，避免把一次抽检结论扩大为全部 SN 结论。
- 追溯、SN 测试和 IPQC 分别校验原有权限；缺少租户上下文时在查询前拒绝。返回公共 DTO 不暴露请求指纹与幂等键。
- 雪花 ID 保持字符串；查询失败、未命中或新扫码发生时不保留旧 SN 的履历。

## 4. AI 批量问答

既有 Supervisor 通过 JSON `AgentInvocation` 包装最终内容，长文本可能在 `done` 外层再次编码时出现解析失败。本轮按实际依赖版本核对 SDK 实现，对纯 ERP 批量文本查询直接调用 `ErpQueryAgent`；图表、报告、知识库、MCP、网络与组合工具任务继续使用原编排路径。

模型调用仍使用原 SQL 工具、安全校验、租户上下文、SSE、用量统计与会话机制。新增包装器检查 `FinishReason.LENGTH`，长度截断时明确报错，不保存为完整答案，也不发送完成事件。未通过统一提高 Token 上限或自动拼接内容掩盖截断。

新版 8080 实测问题：

> 查询全部生产工单，逐条列出工单编号、计划数量、已完工数量、单位、状态、计划开始日期和计划结束日期。先给出总条数，随后完整列出，不要只返回前10条；缺失字段明确标为未记录。不要修改任何数据。

结果：`26` 张工单全部出现，无缺失编号，收到 `AI_DONE`，无 `AI_ERROR`；本次耗时 `28.586` 秒。以提问前捕获的同一份 ERP 列表逐项核对：数量字段 `52` 个、已知单位 `24` 个、状态 `26` 个，差异为 0。两个原始记录没有单位名称，未用猜测值补齐。日期字段未做自动逐项对账。

250 行长文本属于单元回归边界样本，不代表现场存在 250 条业务数据。一次查询耗时也不代表竞赛全部案例、并发压力或正式 SLA 达标。
