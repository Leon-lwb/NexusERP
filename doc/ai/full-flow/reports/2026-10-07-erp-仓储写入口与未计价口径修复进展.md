## 本阶段修复

1. **领料 ATP**：保留真实在库量，独立可用量按在库减预留计算；拒绝未知预留、删除、冻结、过期来源，效期使用数据库日期，空效期排后。实际扣减查询和原子 SQL 同样补删除/未知预留守卫，不能只修候选列表。
2. **PC 范围与恢复**：全仓量只作参考；行上限按仓库、批次、库位确认并绑定范围身份，未知/旧响应不授权执行。PARTIAL 实发后本次清零、原批次耗尽时仍可先选择下一真实库存建立范围，再填写正数；选择不填量、不重置已领、不更换原 ID。只读、终态、SHORT_CLOSED、非法量和正量超 ATP 仍失败关闭。
3. **参考金额**：缺明细、缺价或缺可靠数量，返回 totalAmount=null、referenceAmountKnown=false，已知零价仍可为零。只有明确清价请求才在原合法编辑事务清 NULL；省略字段保留原值。参考金额不是库存实际成本，未用已完成原单的净成本23.34回填历史参考价/额。
4. **PDA 写链**：唯一解析真实物料、仓库、库区、储位、批次、库存；已绑定来源不能扫码悄悄替换，QC 对实际批次。所有分支核原事务已绑定物理连接的实际 RR，不借新连接，DEFAULT 元数据为空不误拒真实 RR。来源绑定、实际扣库、明细/状态/普通及 NULL 汇总在原事务内；关键影响行非1抛异常，不能扣库后忽略零行。
5. **生产入库**：同租户原工单父锁串行草稿/执行/恢复，限制普通终态修改和删除。只有原完整单据、唯一库存流水、物料根单位、真实仓储和批次来源一致才恢复原结果；CLOSED 只支持完整原回执。去掉策略 hasPosted 静默成功。先减已审核报工量再核本次计划量；报工事实改当前锁读，审核 writer 同步为父锁→子当前读→原 CAS→累计回写，避免旧 RR 报工视图与新工单累计混用。
6. **检查入口**：新仓储前端回归实际接入标准 test:unit 链；两条 pickingRule/putawayRule 导入修正大小写，真实 API URL不改，主根物理目录对齐 Git且文件字节不变。
