## 三、代码与安全边界修复

1. **缺料拒绝分类**：证据不完整且不能发布完整结论时，使用有限白名单 `DecisionEvidenceException.SHORTAGE_SIMULATION_INCOMPLETE`，不再由 Flow 包装为泛化错误。公开文案涵盖需求、库存、供给单位及有限计算未完成，不暴露底层消息；局部风险和失败关闭算法保持不变。
2. **知识导入租户／关联**：入口验证精确租户与知识库，工作线程重核文档归属及捕获的知识库；成功／失败写入均在动态租户域，传播并清理 AI 上下文，CallerRuns 不破坏调用线程上下文。历史未知归属不自动认领。
3. **错误信息泄漏**：异步解析／向量化及同步 OSS 上传只返回固定中文公共错误，不把厂商地址、密码、Token 或 cause 写入接口可见字段，诊断只记异常类型。
4. **任务拒绝**：线程池饱和仍保留 CallerRuns 背压，shutdown 明确拒绝而不是静默丢弃；拒绝回写重新核对文档归属并向调用方明确失败。
5. **重试认领与清理**：工作线程使用文档 ID＋精确租户＋知识库＋允许状态的数据库 CAS 原子认领，首次上传只认领 0、重试只认领 0/3；迟到、重复及未认领任务不清理或覆盖成功结果；提交拒绝回写同样使用范围／状态 CAS，不能把另一任务的处理中或成功状态改回可重试。提交入口不先删外部向量；任务实际开始并复核来源／索引后，先删向量、成功后删 SQL 片段。InMemory 按 documentId 精确删除，保留其他文档；Milvus 删除失败明确中止，不以清缓存冒充删除成功。
6. **SQL 契约测试**：兼容当前转储的 COLLATE、整数显示宽度、隐式可空 DEFAULT NULL、数值默认值引号、USING BTREE 及默认 RESTRICT；保留类型、非空、默认值、唯一性、索引顺序、外键和事务负例，不通过忽略字段获得绿色。

新增正式案例盘点工具还通过变异回归拒绝最终动作载荷变化、空 Flow 身份及无实质来源／值的证据空壳；对本轮3个运行的实际309条持久证据分别离线复验，全部通过字段与来源一致性检查。这不等于黄金案例结果或执行闭环通过。

Java 新增方法／边界说明使用中文友好的 Javadoc。没有批量格式化前端或改动原有未跟踪草稿。
