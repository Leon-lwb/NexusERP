## 二、本批代码补丁

### 1. 认证失败的真实诊断与空库存门禁

[preflight](../scripts/procurement_runtime_preflight.py) 与 [对应测试](../scripts/test_procurement_runtime_preflight.py) 增加安全诊断：

- 单个明确上下文保留数值业务码；401、403、429、5xx 不再混成“登录失效”。HTTP 状态通过 `httpStatus` 单独记录，不冒充业务码。
- 多个失败候选只汇总有界固定分类及数值计数；没有唯一新鲜主体时仍阻断，不拼接身份、输出路径/响应本体或猜测密码/令牌有效期。
- 严格 JSON 解码后，非成功响应先处理安全业务码，不因无关非法 ID 字段丢掉 401 等诊断；成功响应仍严格校验原生整数/字符串 ID，布尔 ID 继续拒绝。
- urllib 包装的已知拒绝连接/超时保留固定分类，不输出原因文本。
- 空库存行快照仍要求来源范围、完整性和账本对账，不将 `COALESCE(...,0)` 视为可靠零，也不移除来源门禁。

### 2. 采购/IQC V2 结构前置接线

新增 [结构合同](../scripts/procurement_schema_contract.py) 与 [固定夹具测试](../scripts/test_procurement_schema_contract.py)，人工对照实际 Mapper、全新安装 SQL 及相关增量，声明 ERP **20** 表 + MES **3** 表、**280** 个关键列、**44** 个必需主键/永久唯一键。

主线程将这些表并入 preflight 的同一受控连接目录读取，保留可空性、字符长度、完整原生类型、排序规则、datetime 精度、生成列信息及完整索引部分。缺任一必需表、列、精度或完整唯一键即在首个租户业务行查询前返回。

此为最小写链目录观测合同，不克隆全部基础业务表，不反推历史认证。即使结构匹配，仍仅为 `SCHEMA_METADATA_MATCH`，保留 `sourceCertification=NOT_PERFORMED`、`runtimeWriteChain=NOT_PROVEN`、无业务写/DDL 授权。出生引用、事件序列的历史 nullable 兼容不能升级为真实来源事实。

### 3. 正式脚本受控收货路由与恢复契约

[正式 transport](../scripts/formal_procurement_transport.py) 与 [对应测试](../scripts/test_formal_procurement_transport.py) 续接后端已有两条 POST 路径：

- `/erp/wm/receive/certified/shelf/{receiveId}`：仅上架。
- `/erp/wm/receive/certified/execute/{receiveId}`：独立过账。

分别绑定原始意图，只接受路径原生字符串 ID，不允许请求体/查询覆盖，不自动将 shelf 变成 execute。IQC 只增 GET 本体/明细支持，不开放客户端出生或 IQC CRUD 写授权。

恢复证据契约要求独立读取器核验永久出生、完整 V2/IQC、冻结原来源及终态过账/原流水。通知 `PENDING`，或 `ENQUEUED` 但消费闭合证据缺失，仍为 `UNCERTAIN`；重试需原日志、独立重试证明及新鲜加载证明。

**真正读取这些永久事实并强制执行的独立 reader/生命周期/写授权权威仍需接入。** 本补丁只是脚本路由与结果契约的接线，不能把替身返回的摘要当成正式证明，不能因此声称完整执行入口已开放。
