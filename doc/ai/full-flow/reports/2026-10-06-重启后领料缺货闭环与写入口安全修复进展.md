## 三、运行中发现的问题、同源恢复与正确证据

### 3.1 新增计划未默认落草稿

`POST /erp/prd/plan` 的合法 BO 未提供状态，接口返回成功，但 `SCJH20260007.status=NULL`。实际创建服务只是映射后插入，后续确认只允许 DRAFT，不能仅凭客户端习惯传 DRAFT 认为后端默认值已实现。

主线程先独立核实同一新单尚无 MRP、工单或审批，再通过普通编辑 API 初始化 **同一原单**的 DRAFT／版本／当前标记；原创建意图保留，没有 SQL 伪造审批、另建计划或替代失败来源。然后只生成一次新 MRP，走正常后续流程。这是旧构建下的明确恢复，不是新出生补丁的运行验收。

### 3.2 仅编辑领料单头误删未领明细

首次普通编辑仅选择仓库，未提供 `wmProductionIssueLineList`。旧 `syncLines(NULL)` 把本单三条未领行全部逻辑删除。随后的两次 PDA finish 实际报“生产领料单无明细行”，**没有到达预期非法来源校验**，不算拒绝／回滚测试通过。

恢复前锁定核对：同一新单为 CREATED、三行全部已领 0、无该单库存流水、对应 MRP 实发 0，原行物料／单位／需求归属匹配。基于用户此前本地库写授权，主线程仅在一个本地 ERP 事务内恢复**原三行 `del_flag=0`**；未更改数量、单位、来源、审批、库存、旧完工单或任何财务标记。随后使用完整原列表普通编辑重算单头。条件 UPDATE 恰好影响三行，原 ID 不变；恢复前后和原失败意图均留证。

原先的私有拒绝测试结论用 `shortage-first-attempt-evidence-correction.json` 明确更正，不能拿任意 500 或“数据库没变”当作预期业务守卫已执行。

### 3.3 恢复后的真实短缺清零、回滚与重放

- 再次显式验证非法额外来源行：原三行先进入缺货处理，随后发生预期“缺货声明包含不存在或已领满的行”；系统操作日志核到该准确原因，三行／单头／MRP／工单／库存全部回滚保持原样。
- 以正确三行正常调用 `POST /app/pda/wm/issue/{原单ID}/finish`，`data.ok=true`、`nextAction=FINISHED`；原三行实际持久化为零本次量，单头实际量／金额均为 0。
- 同载荷正常重放返回 `replayed=true`，独立数据库快照不变。没有重复扣库或额外完成制造；原旧完成领料行的历史 `current_qty=6／6／12` 仍保留，未被暗改。
- 这一结果证明此前 **`completeWithShortage` 写零路径**在重启后的实际新单可执行；没有在本轮库存不足的新范围中宣称正数量 `execute` 路径已重新验收，也不把无库存记录当作可信库存 0。
