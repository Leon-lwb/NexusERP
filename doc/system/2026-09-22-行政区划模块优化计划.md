# 行政区划（sys_dic_area）模块优化计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 ERP 行政区划模块的正确性缺陷、补全全国数据、消除前端三处重复的级联实现，并厘清与 nexus-shop / Nexus-App 的边界。

**Architecture:** 后端 `SysDicAreaController` → `ISysDicAreaService` → `SysDicAreaMapper`（表 `sys_dic_area`，位于 `ry-vue` 库，租户隔离）。前端管理页 `views/system/area/index.vue` 按需懒加载；三个业务页（客户/供应商/仓库）各自实现省市区街道四级联动。本次优化：后端修树构建与校验 → 抽公共 composable 消除前端重复 → 数据补全 → 跨端对齐。

**Tech Stack:** Java 17 / Spring Boot 3 / MyBatis-Plus 3.5.16 / Sa-Token / Redis(Redisson Spring Cache)；Vue 3.5 + TS + Element Plus + UnoCSS。

### 2.3 数据现状（`script/sql/ry-vue.sql`，实测解析全部 1661 行）

```
层级分布：layered=1 → 34    layered=2 → 11     layered=3 → 133
          layered=4 → 1481  layered=5 → 2      合计 = 1661
```

> **⚠️ 勘误（2026-09-22，Task 1 代码评审发现）**：本节初版写的是 `124 / 1405`（合计 1576）。原因是初次解析的正则要求 `sort` 非空，**静默漏掉了 85 行 `sort IS NULL` 的记录**（其中 `layered=3` 9 行、`layered=4` 76 行）。正确口径为 **133 / 1481**。Task 11 的验收基线必须用 1481，否则会误判为回归。

**关键发现（已逐行解析验证）：**

1. **34 个"省份"的 `parent_area_id` 全部是 `156`，而 `sys_dic_area` 中不存在 `area_id = 156` 的行。** 即全部省份挂在一个不存在的父节点下。
2. **33 个省份子节点数为 0**；只有 `330000 浙江省` 有 11 个子节点（市）。→ **除浙江外全国省市区数据实际为空。**
3. **孤儿父节点共 9 个**（被引用但无对应行）：`156`、`330204`、`330283`、`330322`、`330621`、`330682`、`330752`、`331021`、`331999`。**共 106 行指向这些不存在的父节点**，其子树无法通过树到达。
4. **存在 `layered = 5` 的 2 行**，而字典 `sys_area_level` 定义 1~5、前端 `hasChildren: item.layered < 4` → 5 级在 UI 上不可达。
5. **`area_id` 无重复（0 组）** —— 实测 1661 行全部唯一。但存在**异常码**：`102`（"经济技术开发区"）、`330150`、`330155`、`330183`、`331051` 等，以及 36 个商城数据集中没有的浙江区县码。
6. **重名严重**：共 **97 组重名**（如 11 行叫"市辖区"、多个"滨海新区"/"溪口镇"），另有两行都叫"富阳区"（`330111` 与 `330183`）。→ 这是"选择上级时选错同名声明的节点"进而成环的现实诱因（见 Task 1 的 C1 修复）。
7. 其他数据质量：部分 `lat`/`lng` 为空串 `''` 而非 NULL；85 行 `sort IS NULL`；`address` 格式不统一（有的全路径、有的只有单个名称）；已撤销的下城区 `330103`、江干区 `330104` 仍存在。

字典与菜单齐备：`sys_area_level`（1省份/2城市/3区县/4街道乡镇/5社区村）、菜单 `20031` + 权限 `20032~20036`。

## 三、问题清单（按优先级）

### 🔴 P0-1 数据基本不可用
证据：§2.3 第 1~3 条。影响：客户/供应商/仓库表单除浙江外选不到任何市区。
> 注：`buildTree` 用 `layered == 1` 找根，所以"省份列表"能显示 34 条，但点开只有浙江有内容——**表面上像能用，实际是空壳**。

### 🔴 P0-2 新建租户无行政区划数据
`sys_dic_area` 含 `tenant_id` 且**不在** `application.yml` 的 `tenant.excludes` 中 → 多租户插件注入租户条件。
而 `SysTenantServiceImpl.insertByBo`（第 186~209 行）开通租户时**只复制 `sys_dict_type`/`sys_dict_data`/`sys_config`，不复制 `sys_dic_area`**。
→ 任何非 `000000` 租户，省市区级联**全空**。

### 🔴 P0-3 按名称搜索恒返回空
```java
// SysDicAreaServiceImpl.java:155-165
List<SysDicAreaVo> roots = areas.stream()
    .filter(a -> a.getLayered() != null && a.getLayered() == 1)   // ← 只认 1 级作根
    .peek(a -> a.setChildren(new ArrayList<>()))
    .collect(Collectors.toList());
```
`/system/area/list?areaName=杭州` → 命中的是 `layered=2` 的行 → 被过滤掉 → `roots` 为空 → 返回 `[]`，且不报错。
任何"过滤条件命中非省级节点"的查询都会静默丢数据。

### 🔴 P0-4 `/list/exclude/{pkid}` 参数被忽略 → 可成环
```java
// SysDicAreaController.java:89-93
@GetMapping("/list/exclude/{pkid}")
public R<List<SysDicAreaVo>> listAreaExcludeChild(@PathVariable(required = false) Long pkid) {
    return R.ok(sysDicAreaService.selectSysDicAreaTreeList(new SysDicArea()));  // ← pkid 从未使用
}
```
注释声称"排除指定节点（用于选择上级时回显）"，实际返回全树。前端 `handleUpdate` 依赖它防止把自己选成自己的上级 → **可形成父子环**，成环后 `buildSubTree` 递归行为不可预期。
另：`required = false` 无意义——路径变量缺失时该 handler 根本不会匹配。

### 🟠 P1-1 删除无子节点校验
`deleteSysDicAreaByPkids` 循环 `deleteById`，不检查是否存在下级 → 产生孤儿节点（正是 §2.3 第 3 条的成因）。且**无 `@Transactional`**。

### 🟠 P1-2 新增/修改无任何业务校验
`insertSysDicArea`/`updateSysDicArea` 直接落库，不校验：子级 `layered` 是否等于父级 `+1`、`areaId` 是否重复（DDL 只有普通索引 `idx_area_id`，无唯一约束）、`parentAreaId` 是否存在、`address` 全路径是否维护。

### 🟠 P1-3 `del_flag` 是死列
`SysDicArea.delFlag` 无 `@TableLogic`（项目其余 **193 处**实体都有），`mybatis-plus.enableLogicDelete: true` 只是"允许"开关，不提供字段。
→ `deleteById` 实为**物理删除**，与列注释"0代表存在 1代表删除"矛盾。

### 🟠 P1-4 编辑时地址拼进街道数字代码
`BdVendor.streetId` / `BdClient.streetId` / `WmWarehouse.streetId` 是 **`String`**，而 `provinceAreaId`/`cityAreaId`/`districtAreaId` 是 **`Long`**（DB 列均为 `bigint`）。
前端 `plus-ui/src/api/erp/bd/{vendor,client}/types.ts` 声明了 `streetName`，但**后端 VO 不返回该字段**（`BdVendorVo.java:119` 的 `streetId` JavaDoc 还写成"详细地址(街道、门牌号等)"，与列注释"街道行政区划ID"冲突）。
后果（`vendor/index.vue:520`、`client/index.vue:589`、`warehouse/index.vue:546`）：
```js
streetOptions.value.find((option) => option.areaId === form.value.streetId)
// option.areaId 是 number（Long 在 JS 安全范围内序列化为数字）
// form.value.streetId 是 string（Java String）
// number === string → 恒 false
```
→ 走兜底分支 `areaName: form.value.streetName || form.value.streetId` → `streetName` 不存在 → **街道名显示为数字代码，并被拼进 `address`**。

### 🟠 P1-5 `SysDicAreaVo` 缺时间字段 + 导出风险
- 前端 `index.vue:18-22` 渲染"创建时间"列用 `proxy.parseTime(scope.row.createTime)`，但 VO 无该字段 → **恒空白**。
- `export` 传 `SysDicAreaVo.class`，该类**无任何 `@ExcelProperty`**，且含 `List<SysDicAreaVo> children` → FastExcel 写 `List` 字段有抛异常风险，**需实测**。导出还是全量平铺（1661 行）无层级。

### 🟡 P2-2 三处级联逻辑重复

`plus-ui/src/components/` 下**没有任何共享行政区划组件**。

### 🟡 P2-3 性能与缓存
- `buildSubTree` 对每个父节点全量扫描一次 `areas` → O(n²)，n=1661 时约 270 万次比较。
- 整个读取链路**无缓存**，而项目已具备 Redisson Spring Cache（`CacheConfig` + `CacheNames` + `CacheUtils`，`@Cacheable`/`@CacheEvict` 已广泛使用）。
- `selectProvinces`/`selectNextLevel` 用 `select *`、硬编码 `layered = 1`、不过滤 `del_flag`。
- 三个业务页每次进入表单要打 `1 + N` 次请求（省 1 次 + 每级 1 次）。

### 🟡 P2-4 契约与规范
- `/system/area/list` 同一 URL 返回树或平铺（取决于 `parentAreaId`），调用方无法从契约得知。
- `add`/`edit` 直接用实体接收请求体（项目约定是 `domain/bo`）→ 客户端可传 `tenantId`/`delFlag`/`createBy` 等**越权字段**；无分组校验。

### 阶段 0：决策 ✅ 已确认（2026-09-22）

- [x] **决策 1：数据来源策略 = 方案 A**（从商城 `eb_system_city` 导入）

  零外部依赖，同一 MySQL 实例可直接 `INSERT ... SELECT`。转换要点：商城 `level` 是 **0=省/1=市/2=区县**（与 ERP 的 `layered` **1=省…4=街道** 方向相反）；商城 `city_id` 是**合成自增 ID**（非 GB 码），GB 码存在 `area_code`（12 位，如 `'110101000000'`）；ERP 的 `area_id` 是 6 位或 9 位 GB 码（如 `330102`、`330102001`）。

  **已确认的两项限制（务必写入交付说明）：**
  1. 商城数据**只到区县（3 级）**，不含街道/乡镇；ERP 现有浙江街道数据（`layered=4`）需**保留**而非覆盖。
  2. 商城的**香港/澳门/台湾**数据（348 行）`area_code` 为 `'0'` 或空，**无可用 GB 码**，无法迁移；ERP 的 `810000`/`820000`/`830000` 三个省级行保留即可（仅需修正父级）。

- [x] **决策 2：多租户策略 = 方案 A**（`sys_dic_area` 加入 `tenant.excludes`）

  行政区划是**国家标准参考数据**，本不该按租户隔离；改动最小、一次性解决所有现存与未来租户。
  `SysDicArea` 的 `tenantId` 字段与列保留（无害），但查询不再注入租户条件。已确认无代码依赖"按租户隔离行政区划"的语义。

```java
    /**
     * 由扁平列表构建森林。
     * <p>根 = 父节点不在结果集中的节点（而非"层级为 1"），因此：
     * 过滤条件命中任意层级时都不会丢数据；父节点缺失的孤儿节点会升级为根，不会不可见。
     * 单次遍历 + Map 索引，复杂度 O(n)。</p>
     */
    private List<SysDicAreaVo> buildTree(List<SysDicAreaVo> areas) {
        if (CollUtil.isEmpty(areas)) {
            return new ArrayList<>();
        }
        Map<Long, SysDicAreaVo> byAreaId = new LinkedHashMap<>(areas.size());
        for (SysDicAreaVo area : areas) {
            area.setChildren(new ArrayList<>());
            if (area.getAreaId() != null) {
                byAreaId.put(area.getAreaId(), area);
            }
        }
        List<SysDicAreaVo> roots = new ArrayList<>();
        for (SysDicAreaVo area : areas) {
            SysDicAreaVo parent = area.getParentAreaId() == null ? null : byAreaId.get(area.getParentAreaId());
            // 父节点缺失，或脏数据把自己当父节点 → 升级为根，避免节点丢失或自环
            if (parent == null || parent == area) {
                roots.add(area);
            } else {
                parent.getChildren().add(area);
            }
        }
        return roots;
    }
```

```ts
import { ref, type Ref } from 'vue';
import { getProvinces, getNextLevel, type AreaVO } from '@/api/system/area';

/** 地址表单中与行政区划相关的字段 */
export interface AreaAddressForm {
  provinceAreaId?: string | number | null;
  cityAreaId?: string | number | null;
  districtAreaId?: string | number | null;
  streetId?: string | number | null;
  address?: string;
  [key: string]: any;
}

type Level = 'city' | 'district' | 'street';

/**
 * 省 / 市 / 区县 / 街道 四级联动。
 *
 * 关键点：后端 provinceAreaId 等为 Long、streetId 为 String，
 * 因此一律用 String(id) 比较，避免 number === string 恒 false
 * 导致街道名退化成数字代码（见 2026-09-22 行政区划优化计划 P1-4）。
 */
export function useAreaCascade(form: Ref<AreaAddressForm>) {
  const provinceOptions = ref<AreaVO[]>([]);
  const cityOptions = ref<AreaVO[]>([]);
  const districtOptions = ref<AreaVO[]>([]);
  const streetOptions = ref<AreaVO[]>([]);

  const sameId = (a: unknown, b: unknown) => a != null && b != null && String(a) === String(b);
  const nameOf = (list: AreaVO[], id: unknown) => list.find((o) => sameId(o.areaId, id))?.areaName ?? '';

  async function loadProvinces() {
    provinceOptions.value = (await getProvinces()).data ?? [];
  }

  async function loadChildren(level: Level, parentId: string | number) {
    const list = (await getNextLevel(parentId)).data ?? [];
    if (level === 'city') cityOptions.value = list;
    else if (level === 'district') districtOptions.value = list;
    else streetOptions.value = list;
  }

  /** 清空指定层级以下的选项与选中值 */
  function resetBelow(level: 'province' | 'city' | 'district') {
    if (level === 'province') {
      form.value.cityAreaId = null;
      cityOptions.value = [];
    }
    if (level === 'province' || level === 'city') {
      form.value.districtAreaId = null;
      districtOptions.value = [];
    }
    form.value.streetId = null;
    streetOptions.value = [];
  }

  function updateAddress() {
    const parts = [
      nameOf(provinceOptions.value, form.value.provinceAreaId),
      nameOf(cityOptions.value, form.value.cityAreaId),
      nameOf(districtOptions.value, form.value.districtAreaId),
      nameOf(streetOptions.value, form.value.streetId)
    ].filter((p) => p !== '');
    form.value.address = parts.join('');
  }

  async function onProvinceChange(value: string | number | null) {
    resetBelow('province');
    if (value) await loadChildren('city', value);
    updateAddress();
  }

  async function onCityChange(value: string | number | null) {
    resetBelow('city');
    if (value) await loadChildren('district', value);
    updateAddress();
  }

  async function onDistrictChange(value: string | number | null) {
    resetBelow('district');
    if (value) await loadChildren('street', value);
    updateAddress();
  }

  function onStreetChange() {
    updateAddress();
  }

  /** 编辑/查看态逐级回显 */
  async function loadAddressCascade() {
    await loadProvinces();
    if (!form.value.provinceAreaId) return;
    await loadChildren('city', form.value.provinceAreaId);
    if (!form.value.cityAreaId) return;
    await loadChildren('district', form.value.cityAreaId);
    if (!form.value.districtAreaId) return;
    await loadChildren('street', form.value.districtAreaId);

    // 街道可能因数据缺失而不在下拉中，补一个显式占位项，避免显示成裸数字代码
    const sid = form.value.streetId;
    if (sid && !streetOptions.value.some((o) => sameId(o.areaId, sid))) {
      streetOptions.value.push({
        areaId: sid as any,
        areaName: `已选街道（${sid}）`,
        parentAreaId: form.value.districtAreaId as any
      } as AreaVO);
    }
  }

  return {
    provinceOptions,
    cityOptions,
    districtOptions,
    streetOptions,
    loadProvinces,
    loadAddressCascade,
    onProvinceChange,
    onCityChange,
    onDistrictChange,
    onStreetChange,
    updateAddress
  };
}
```

- [ ] **Step 4: 合并区县（含"直筒子市"9 位码特殊处理）**

**这是本任务最容易踩的坑**：商城有 3 个**直筒子市**（不设市辖区，市下直接是镇/街道），其"市"与"镇"的 `area_code` **前 6 位相同**：

| 市 | 6 位码 | 冲突行数 |
|---|---|---|
| 东莞市 | `441900` | 36 |
| 中山市 | `442000` | 25 |
| 儋州市 | `460400` | 24 |

若一律 `LEFT(area_code, 6)`，这 85 行会全部塌缩成同一个 `area_id`，**违反唯一性**。处理规则：**当区县的 6 位前缀与其父市相同时，改用 9 位码**。

```sql
-- 区县：商城 level=2 → ERP layered=3
INSERT INTO sys_dic_area (area_id, parent_area_id, area_name, lng, lat, layered, sort, address, del_flag, tenant_id, create_time)
SELECT
  CASE WHEN LEFT(c.area_code, 6) = LEFT(p.area_code, 6)
       THEN CAST(LEFT(c.area_code, 9) AS UNSIGNED)     -- 直筒子市：镇/街道用 9 位码避免碰撞
       ELSE CAST(LEFT(c.area_code, 6) AS UNSIGNED)
  END,
  CAST(LEFT(p.area_code, 6) AS UNSIGNED), c.name,
  NULLIF(c.lng, ''), NULLIF(c.lat, ''), 3,
  ROW_NUMBER() OVER (PARTITION BY p.id ORDER BY c.id),
  CONCAT(IFNULL(gp.name, ''), ' ', p.name, ' ', c.name), '0', '000000', NOW()
FROM crmeb.eb_system_city c
JOIN crmeb.eb_system_city p  ON p.city_id = c.parent_id
LEFT JOIN crmeb.eb_system_city gp ON gp.city_id = p.parent_id
WHERE c.level = 2
  AND LENGTH(c.area_code) = 12 AND LENGTH(p.area_code) = 12
  AND NOT EXISTS (
    SELECT 1 FROM sys_dic_area d
    WHERE d.area_id = CASE WHEN LEFT(c.area_code, 6) = LEFT(p.area_code, 6)
                           THEN CAST(LEFT(c.area_code, 9) AS UNSIGNED)
                           ELSE CAST(LEFT(c.area_code, 6) AS UNSIGNED) END
  );
```

> **直筒子市映射到 `layered=3` 的语义妥协**：这些行本质是镇/街道（GB 码第 9 位段），但因其父市没有区县层级，把它们放在 3 级才能维持 `layered = 父级 + 1` 不变量（Task 4 的校验会拒绝 2→4 的跳级）。**须在文档中记录该妥协**。

## 七、风险与注意事项

1. **缓存类型信息陷阱（来自商城 2026-09-21 生产事故）**
   商城 `/api/front/city/list` 曾因 Redis 缓存内嵌 Jackson `@class` 类型信息、包名重构后无法反序列化而**持续 500**。
   → 本项目若改包名/类名，**必须同时清空 `sys_dic_area_tree` 缓存**。上线清单加入此步。

2. **数据合并是增量、不可回退的**
   Task 11 采用 `INSERT ... WHERE NOT EXISTS` **增量合并**（不是清空重建）。仍**务必先** `CREATE TABLE sys_dic_area_bak_20260922 AS SELECT * FROM sys_dic_area`，并在合并后核对 `bd_client`/`bd_vendor`/`wm_warehouse` 中已有的 `province_area_id` 等值仍能在新数据中解析到。
   **切勿改用 `TRUNCATE` + 全量导入** —— 实测会丢失 **1481 行浙江街道**、2 行 `layered=5`、**36 个商城 2021 快照未收录的浙江区县**（如 `330113` 临平区、`330114` 钱塘区）。

3. **层级方向相反**
   商城 `level` 0 起（0=省），ERP `layered` 1 起（1=省）。任何数据搬运都必须显式转换，**不可直接搬**。

4. **直筒子市的编码碰撞（易漏）**
   东莞 `441900`、中山 `442000`、儋州 `460400` 三个市不设市辖区，其"市"与下辖镇/街道的 `area_code` **前 6 位相同**。一律取 6 位会让 85 行塌缩成同一个 `area_id`。Task 11 Step 4 已用"前缀与父市相同时取 9 位"处理，**不可简化掉**。

5. **街道层级仍然缺失（浙江除外）**
   商城数据只到区县。非浙江地区的街道下拉为空——`streetId` 可空，不阻塞主流程。需街道/乡镇数据时须另找数据源。

6. **港澳台无下级**
   商城的香港/澳门/台湾 348 行 `area_code` 为 `'0'`/空，无 GB 码，无法迁移。ERP 的 `810000`/`820000`/`830000` 保留为无子节点的省级行。

7. **`area_id` 命名冲突**
   `sys_dic_area.area_id` = 行政区划代码；`wm_storage_area.area_id` = **库区ID**。两者语义完全不同，grep `area_id` 时务必区分上下文。这也是前端 `AreaVO.areaId` 与仓库模块 `areaId` 容易混淆的根源。

8. **`@TableLogic` 启用后的行为变化**
   启用后所有 `deleteById`/`deleteByIds` 变 UPDATE，且查询自动追加 `del_flag='0'`。需确认无代码依赖物理删除语义（已确认：`SysDicArea` 无其他调用方）。

9. **Nexus-App 的权限前置**
   Task 13 启动前必须确认 App 角色已有 `system:area:list`，否则 403 会被误判为接口问题。
