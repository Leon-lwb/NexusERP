# Nexus-ERP 与主流 MES/ERP/IoT/AI 功能差距分析

> 文档编号: NexusERP-ANALYSIS-2026-001
> 创建日期: 2026-07-29
> 状态: 已发布
> 信息来源: doc/PROGRESS.md(2026-07-29 更新)、doc/PLANS.md、各模块主文档(ERP/MES/IoT/AI)、代码结构扫描(4 个子代理并行提取 controller/service/前端覆盖)
> 对标产品:
> - ERP: SAP S/4HANA、Oracle Cloud ERP、用友 YonBIP、金蝶 Cloud Cosmic、Microsoft Dynamics 365
> - MES: Siemens Opcenter、Rockwell FactoryTalk、GE Proficy、鼎捷数智 MES、用友 MES、MESA-11 / ISA-95 标准
> - IoT: AWS IoT Core、Azure IoT Hub、PTC ThingWorx、阿里云 IoT、华为云 IoT
> - AI: Dify / RAGFlow / Coze(通用平台)+ 工业视觉/预测性维护/智能排产平台(工业 AI)

> 严重度图例: 🔴 严重(定义性缺失) / 🟠 显著(主流标配而本系统缺) / 🟡 中等(有基础但不完整或非核心)

## 总体定位

Nexus-ERP 当前实质是 **"进销存 + 生产 + 仓储"中型 ERP + 较完整 MES + 基础 IoT + 通用 AI 对话层** 的组合。供应链核心(ERP bd/so/pu/prd/sch/wm 六领域 93–98% 完成)和制造执行(MESA-11 约 65% 覆盖)是强项;**ERP 财务核心完全缺失**是最大短板,**工业 AI 专用能力几乎空白**是制造业场景下最可惜的差距。

| 模块 | 完成度 | 对标主流 | 核心差距 |
|---|---|---|---|
| ERP | 供应链 95% / 财务 0% | SAP/Oracle/用友/金蝶 | 财务核心(GL/AR-AP/FA/CO/预算)全缺 |
| MES | MESA-11 约 65% | Siemens Opcenter/鼎捷/用友 | APS 排产、人员技能、预测性维护 |
| IoT | 阶段一 16/18 完成 | AWS/Azure/阿里云/ThingWorx | 多协议、设备影子、OTA、边缘 |
| AI | 通用层强 / 工业 AI 0% | Dify/RAGFlow + 工业视觉平台 | 视觉质检、预测性维护、智能排产 |

---

## ERP 差距

**已实现(完整)**:基础数据(物料/BOM 多版本/工艺路线三层模型/替代料)、销售(报价 -> 订单 -> 合同 -> 发票 -> 红冲/核销,含四级定价引擎 + 信用检查)、采购(申请 -> 订单 -> 合同 -> 进项发票 + 三单匹配 + 认证子状态机)、生产(工单/MRP/委外/返工/倒冲)、排产调度(班次/班组/考勤/App 打卡)、仓储(12 种库存策略/3D 可视化/批次/SN/条码/正反向追溯/移动平均估值)。

**与主流 ERP 差距**:

| 能力域 | 主流 ERP | Nexus-ERP | 等级 |
|---|---|---|---|
| **总账 GL**(科目表/凭证/日记账/试算) | 标配 | 完全不存在 | 🔴 |
| **应收应付 AR/AP**(核销/账龄) | 标配 | spec 已设计 P3,`com.nexus.erp.fin` 包为空,未编码 | 🔴 |
| **固定资产 FA**(折旧/处置) | 标配 | 无 | 🔴 |
| **成本核算 CO**(标准/实际成本/差异) | 标配 | 无 | 🔴 |
| **预算管理** | 标配 | 无 | 🔴 |
| **多组织/多法人** | 标配 | 仅租户隔离,无公司/法人独立核算 | 🟠 |
| **APS 高级排程** | 标配 | 无(仅有班次/产能日历基础数据) | 🟠 |
| **HR/薪资** | 标配 | 无(仅排产考勤) | 🟠 |
| **CRM / SRM / TMS / 项目管理** | 模块化提供 | 全缺 | 🟡 |
| **BI/报表** | SAC/Power BI 级 | 仅积木报表基础 | 🟡 |

**结论**:财务核心缺失使系统停留在"进销存 + 生产"层级,无法与 SAP/Oracle/用友/金蝶在财务维度竞争。`FinancialThreadPoolConfig` 已建但无消费者——框架就绪,业务空缺。建议补齐顺序:**总账 -> AR/AP(P3 已有 spec)-> 固定资产 -> 成本核算**。

## MES 差距

**已实现(完整)**:工单全生命周期(7 状态 + Flowable 审批)、工序派工(扫码开工/完工 + Lock4j 并发)、流转卡引擎(5 态)、进站/出站/跳站校验(5 类规则)、SN 追溯 + 批次管理(FEFO/隔离/消耗/绑定)、MBOM 快照、安灯 + SSE、NCR 不合格品 + 返工 + 8D、IQC/IPQC/OQC 三链路、SPC(5 种控制图 + OOC + 安灯联动 + Cp/Cpk)、设备管理(OEE/备件/巡检/维修/监控大屏/故障统计)、工装管理、eSOP(版本/审批/工位推送)、IoT 设备联动。

**MESA-11 覆盖**:8/11 功能区达 70%+,整体约 65%。短板集中在:

| 能力 | 主流 MES | Nexus-ERP | 等级 |
|---|---|---|---|
| **APS 高级排产**(有限产能/甘特图/插单重排/约束优化) | 内置或独立模块 | 无 | 🔴 |
| **工时管理**(标准工时定额/效率分析) | 标配 | 无 | 🟠 |
| **人员技能矩阵/资质认证** | 标配 | 仅有进站校验框架,无技能管理 | 🟠 |
| **预测性维护**(振动/温度 ML 预测) | 标配 | 仅定时保养 | 🟠 |
| **能耗管理** | 标配 | 无 | 🟠 |
| **PLC/SCADA 深度对接**(OPC-UA/Modbus) | 原生 | 仅 MQTT | 🟠 |
| **多工厂协同** | 标配 | 单工厂架构 | 🟠 |
| **移动端 PDA**(扫码/报工/检验) | 标配 | 仅 App 考勤 | 🟡 |
| **MSA/FMEA/PPAP**(IATF 16949) | 内置 | 无 | 🟡 |
| **数字孪生 / 行业包** | 集成 | 无(3D 仓库是仓储可视化,非车间仿真) | 🟡 |
| **电子签名 + DHR 批记录** | 标配(医药/医疗器械) | P0-6 延后 | 🟡 |

**结论**:MES 是 Nexus-ERP 最强模块,离散制造核心流程完整。**APS 排产是最大短板**——主流 MES 均有,直接影响产能利用率。其次人员/工时/预测性维护构成"资源管理"短板。

## IoT 差距

**已实现(完整)**:内嵌 Moquette Broker、设备认证鉴权(deviceCode + secret,常量时间比较)、Topic 租户隔离 ACL、Redis Stream 消息管道(生产/消费/毒消息隔离/批量落库)、物模型属性解析、设备最新值缓存、SSE 实时仪表盘、硬编码阈值告警 + 安灯联动、心跳检测/数据清理/Stream 裁剪、IoT 自动采集归档到 MES(近期提交)、设备状态同步。

| 能力 | 主流 IoT 平台 | Nexus-ERP | 等级 |
|---|---|---|---|
| **多协议接入**(OPC-UA/Modbus/CoAP/HTTP/LoRaWAN) | 全协议 | 仅 MQTT(TCP),无 TLS | 🔴 |
| **设备影子/数字孪生**(AWS Shadow/Azure Twin) | 标配 | 无,状态靠轮询 | 🔴 |
| **OTA 固件升级** | 标配 | P2 待办,未实现 | 🟠 |
| **边缘计算**(Greengrass/IoT Edge,断网续传) | 标配 | 无 | 🟠 |
| **时序数据库**(Timestream/TDengine) | 内置 | MySQL 存时序,千万行才迁移 | 🟠 |
| **复杂规则引擎 CEP**(SQL 规则/时间窗口/多转发) | 标配 | 仅硬编码阈值 | 🟠 |
| **告警生命周期**(ACK/RESOLVE/抑制/升级) | 标配 | 仅推送 | 🟡 |
| **安全**(TLS 8883 + X.509 证书) | 强制 | 无 | 🟠 |
| **Broker 集群/水平扩展** | 百万级设备 | 单节点 Moquette < 1000 设备 | 🟠 |
| **物模型管理 UI**(JSON Schema 属性定义) | 标配 | 硬编码属性,无编辑器 | 🟡 |
| **数据转发**(Kafka/HTTP/Function) | 标配 | 无 | 🟡 |

**结论**:数据流全链路打通且与 MES 联动是亮点,但**单协议 + 单节点 Broker + 无设备影子/OTA/边缘**使其停留在"轻量设备接入"层级,无法支撑工厂级工业 IoT 部署。阶段二已规划 OPC-UA/规则引擎/TDengine/边缘网关(共约 18 人天),但均未启动。

## AI 差距

**已实现(完整或代码完成)**:8 厂商动态接入(策略模式 + 缓存)、SSE 流式对话(9 种事件)、RAG 完整管线(Tika 解析 + 句子分段 + 混合检索 + RRF + 3 路 Rerank)、知识图谱(GraphRAG:实体抽取 + 标签传播社区检测 + 全局检索 + Agent 工具,**已落库有运行数据,但有 P1-6/P1-7 Bug 待修**)、NL2SQL(7 层安全:SELECT-only/危险词黑名单/表名白名单/tenant 隔离/LIMIT/超时/Few-Shot)、MCP 工具市场、文生图(通义万相)、联网搜索、thinking token、Token 用量统计 + 成本分析、Prompt 模板 + A/B 测试。

**通用对话层对标 Dify/RAGFlow 差距不大**。差距在:

| 能力 | 主流企业 AI | Nexus-ERP | 等级 |
|---|---|---|---|
| **工业视觉质检**(缺陷检测/尺寸/划痕) | 定制 CNN/视觉平台 | 完全空白 | 🔴 |
| **预测性维护 ML**(LSTM/异常检测) | 标配 | Phase 4 仅规划简单趋势,无 ML | 🔴 |
| **智能排产 AI**(遗传算法/约束求解) | 标配 | 无 | 🔴 |
| **异常检测 ML**(自适应基线/孤立森林) | 标配 | SPC/IoT 均固定阈值 | 🟠 |
| **Agent 多轮自主工具调用** | LangChain/AutoGen 标配 | P2-6 待做,当前单轮 Supervisor | 🟠 |
| **多模态理解**(图片/文档/图纸) | GPT-4V/Gemini | 仅有文生图,无理解 | 🟠 |
| **Agent 长期记忆**(Mem0/MemGPT) | 标配 | 无 | 🟡 |
| **AI 工作流引擎**(LangGraph/Dify Workflow) | 标配 | Phase 6 未开始 | 🟡 |
| **模型评估/可观测**(评测集/Leaderboard) | 标配 | 无 | 🟡 |
| **OCR/文档智能**(发票/合同识别) | 标配 | 无 | 🟡 |
| **细粒度权限**(按模型/工具/知识库 RBAC) | 标配 | 仅功能级 Sa-Token | 🟡 |

**结论**:通用 AI 能力是差异化优势(国内 ERP 友商的 AI 普遍弱于此)。但**工业 AI 专用能力几乎空白**——而视觉质检/预测性维护/智能排产恰恰是制造业 AI 回报最高的场景,也是 Nexus-ERP 作为制造业系统对比通用 AI 平台的核心差异化价值所在。Phase 3-6(MES/IoT/跨系统智能赋能)有规划但**代码完全空白**。

## 跨模块/架构差距

- **ISA-95 层次**:L4 企业层(ERP)完整 -> L3 制造层(MES)65% -> **L2 控制层仅 MQTT,无 OPC-UA/Modbus,断层** -> L1 设备层经 IoT 间接覆盖。L2 -> L3 的工业协议断层是贯通数字化的关键阻塞。
- **AI 智能赋能断层**:AI Phase 3-6(MesProductionTool/MesQualityTool/IotDeviceTool/预测性维护/跨系统决策)完全空白,导致 AI 能力停留在"对话查询",未深入业务闭环。
- **合规缺口**:电子签名延后、DHR 批记录未做、审计轨迹仅操作日志——影响医药/医疗器械等受监管行业。

## 优先级建议(按"补齐后价值 / 差距严重度")

1. **🔴 ERP 财务核心**:总账 + AR/AP(P3 spec 已就绪,可直接开工)-> 固定资产 -> 成本核算。这是从"进销存"升级为"ERP"的定义性补齐。
2. **🔴 工业 AI 三件套**:视觉质检(接 IQC/IPQC)、预测性维护(接 IoT 设备数据 + ML)、智能排产(接 sch 产能数据 + 约束求解)。发挥 MES + IoT + AI 组合的差异化价值。
3. **🟠 IoT 工业化**:OPC-UA/Modbus 协议适配 + 设备影子 + OTA + TLS。打通 L2 -> L3,支撑工厂级部署。
4. **🟠 MES APS 排产 + 人员/工时**:补齐 MESA-11 最弱两域。
5. **🟡 AI 工程化**:Agent 多轮调用(P2-6)、模型评估、细粒度权限、知识图谱 Bug 修复。
