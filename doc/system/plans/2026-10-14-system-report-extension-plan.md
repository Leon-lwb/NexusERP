# NexusERP 自研报表功能扩展计划

> 文档编号：NexusERP-REPORT-2026-003；版本：v1.0。
> 状态：E0 + E1 已于 2026-10-14 获用户批准，并完成实施计划中的代码与本机验证；其他阶段待审。
> 创建 / 更新日期：2026-10-14；代码基线：codex/report-module-plan@8bacd044。
> 关联：[原建设设计](../specs/2026-10-13-system-reporting-design.md)、[源码调研](../specs/2026-10-13-system-reporting-research.md)、[首期验证](./2026-10-14-system-report-p0-verification-report.md)、[首期补齐验证](./2026-10-14-system-report-p0-continuation-verification.md)、[使用指南](../guides/NexusERP_自研报表模块使用指南.md)。

目标：将现有 TABLE / DOCUMENT 报表升级为业务人员可持续维护的报表平台，逐步具备自助取数、交叉分析、业务单据打印、仪表盘和自动化交付能力。继续使用 ruoyi-report，自研定义、运行、设计器和策略核心；基础库负责文档编码、图表绘制、条码及存储协议。

## 1. 已有能力与实际边界

基线已交付：自有 DSL v1 / engine 1.0.0，可信 provider 与精确类型，报表及数据集 ACL，草稿 revision，不可变发布与回滚，LIVE / SNAPSHOT，中文测量和分页，持久 PDF / 明细 XLSX / 样式 XLSX 任务，原生设计器和运行页面，6 类初始业务模板。最新补齐固定运行的 RenderPlan 与字体，以及跨批次私有存储恢复。

截至基线验证，相关后端选择器 278 用例、前端报表专项 60 用例通过；这些是既有提交的证据，不能作为未来扩展验收。生产部署、业务签收、峰值内存/吞吐及共享存储集群验证未完成。

| 实际接缝   | 代码事实                                                                  | 扩展要求                                                           |
| ---------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 引擎升级   | ReportCompiler 和 versionDsl 只接受 schema 1 / engine 1.0.0               | 引入显式版本执行器注册；旧发布不因新版本默认值改变                 |
| 数据集版本 | 后端绑定 datasetVersionId；设计器字段列表按 datasetCode 从当前目录选取    | 新增历史契约读取和升级差异确认，分别绑定目录版本与当前草稿         |
| 自助取数   | ReportProviderRegistry 注册代码安装的 provider；数据集版本保存 descriptor | 新增查询模型及版本、目录发布、按固定数据集版本解析执行器           |
| 版式       | 一个增长明细区、固定区域合并、无图片/条码/交叉表模型                      | 有需要时新增 DSL v2 和 RenderPlan v2，保留 v1                      |
| 存储       | ReportArtifactStore 的 read/temporary 等返回本地 Path                     | 共享对象存储需补流式读写和受限本地 materialize，不能只替换配置地址 |
| 运行治理   | 持久 lease 与用户/租户准入已有；全局限额近似；尚无规模实测                | 增加监控、硬配额、任务进度、恢复及容量基准                         |
| 业务入口   | 通用报表页面与 6 个模板已有                                               | 增加业务单据入口、参数选择器和可复用模板包                         |

## 2. 路线选择与建议

| 路线                             | 优点                                           | 代价与适用范围                                           |
| -------------------------------- | ---------------------------------------------- | -------------------------------------------------------- |
| A：持续增加代码 provider / 模板  | 上线简单，业务口径与权限较明确                 | 每次新组合依赖开发；适合当前业务先扩充，长期自助能力有限 |
| B：可信 provider + 受控查询模型  | 先保留稳定业务数据集，再给业务人员开放受控组合 | 需要实体目录、关系基数、行列策略和查询编译；建议采用     |
| C：优先通用 SQL / 全功能 BI 引擎 | 理论覆盖范围广                                 | 多租户、成本、跨库和兼容工作量大；当前不选作第一步       |

建议 B，实施顺序为：E0 兼容与基准 → E1 设计/复用/业务接入 → E2 受控自助取数 → E3 交叉分析 → E4 打印增强 → E5 仪表盘 → E7 自动化交付。E6 共享存储与集群治理为生产规模路线，测量可从 E0 开始，必须在多节点上线前完成；不因排在表格后面而推迟部署所需条件。

E0 + E1 已实施，改善了现有报表的设计、复用和业务接入，并为后续引擎与数据契约升级提供基础。结果见 [验证报告](./2026-10-14-system-report-e0-e1-verification-report.md)；后续优先推进 E2 的受控查询目录，生产多节点上线前先完成 E6。

### E0：版本兼容、基准和可观测性

- 抽出 ReportEngineExecutor / ReportEngineRegistry，按 schemaVersion + engineVersion 分发编译、布局和产物读取；v1 的精确值、权限、分行、页码、合并和导出语义保持独立回归。执行器为代码内受控注册，不接受远程代码插件。
- 运行、发布、草稿预览、回滚和后台任务都经同一分发入口，避免只改预览后旧导出失效。新发布使用明确版本，旧版本原文/校验和不改写；需要升级的定义以新草稿、新发布版本完成。
- 维护支持矩阵和能力声明；安全原因禁用旧引擎时明确拒绝及审计，不以“兼容”继续执行存在问题的实现，也不静默改用新引擎重新计算旧运行。
- 测量取数、计算、快照写入、布局、序列化、导出和下载分段耗时；记录匿名化 runId、状态、行数、页数、输出字节、队列等待和尝试次数。指标标签不包含租户原名、参数值或业务明细。
- 在隔离样本上建立 5,000 行 DOCUMENT、100,000 行明细导出的基准，并检查取消/失败/异常退出后的私有临时文件。SXSSF 当前使用通用临时设施，需要单独验证受限位置与崩溃残留；不能仅凭流式 API 判定磁盘与内存有界。

验收：v1 黄金样本升级前后布局与精确值相同；v1 发布在有 v2 执行器的实例上仍按 v1 工作；未知版本明确拒绝；重启后读固定计划不重新排版；性能记录有硬件、JVM、行列宽度、冷暖条件及真实峰值 RSS。第一轮形成基准，第二轮同环境回归目标不高于基准 120%，超出须解释；没有已测吞吐或内存承诺。

### E1：设计体验、模板复用和业务入口

- 拆分当前 designer/index.vue / model.ts 的编辑状态、列操作、固定区域、参数、校验和保存流程；沿用原生 Vue / Element Plus 和现有撤销/重做。
- 增加多选、复制/粘贴、行列批量样式、键盘操作、列宽拖动、对齐和网格吸附、错误定位及分栏预览。所有编辑动作进入同一 undo/redo 命令；无障碍和离开页面时未保存提醒同时验收。
- 增加历史 datasetVersionId 查询接口；字段列表、参数、样例预览均使用草稿绑定的版本。目录升级不自动替换模板；显式展示新增/删除字段、类型、单位、币种和权限差异，再保存新 revision。
- 增加“复制为新模板”和模板包导入/导出。包包括格式版本、定义、数据集依赖和 checksum，不携带 ACL、用户/租户标识、业务快照或密钥；业务对象 ID 类默认参数需要清空或在目标租户显式映射。导入映射本租户已授权的数据契约，不安装未知 provider，也不直接发布。
- 复用现有 provider 增加报表场景。优先给采购订单、送货单增加“报表预览/打印”入口，业务页面传递单据 ID，再由服务器重新验证单据范围。历史首次模板与用户自建模板不被初始化覆盖。
- 参数新增客户/供应商/仓库/物料等白名单选择器、单据检索、日期区间及联动；lookup 自带业务权限、部门/租户过滤和分页，ID 全程字符串。先以代码注册的“数据集契约版本 + 参数名”映射选择器，不向旧 DSL v1 添入未定义字段；日期区间映射已声明的两个 DATE 参数。无权限对象不会进入候选列表。
- 运行/导出页增加进度、执行阶段、失败分类、数据时间和重试说明。自动重试沿用原任务幂等逻辑；手动重试只处理定义好的可重试失败，保持原运行与权限，不默默重新取数。

验收：已有六类模板复制→编辑→保存→发布→运行→导出闭环；两个数据集版本同时存在时编辑旧模板不使用新字段；多选/粘贴/撤销后 JSON 往返一致；并发草稿仍拒绝覆盖；导入跨租户依赖被拒绝或要求显式映射；业务单据入口无法越权访问；前端实际点击和真实后端联调均记录证据。

### E2：受控自助取数与查询目录

- 第一版只支持一个配置为 ERP 的数据源。由代码中的 EntityCatalogProvider 提供已批准实体、稳定字段 ID、精确类型、主键、业务权限、敏感列、单位/币种维度、tenant / logical-delete / organization / ownership 策略及关系基数。首批只开放库存、物料、仓库、客户/供应商及经确认的订单头/明细。
- 用户操作“实体/字段/筛选/排序/分组/已批准关系”，保存自有 QueryModel v1；用户提交逻辑 ID 和值，不提交 SQL 片段、表名、连接串、脚本或外部 URL。FROM/JOIN/表达式由白名单目录生成，值统一绑定参数。
- 第一版限制为主实体 + 最多 2 个已批准 JOIN、最多 40 个输出字段、20 个筛选条件和 3 个分组维度。禁止 CROSS JOIN、任意子查询、UNION、写操作和系统目录；在当前 MySQL 5.7 基线上不依赖 CTE 或窗口函数。扩展语法另行设计和测试。
- 关系目录区分 1:1、n:1、1:n。1:n 关系涉及主表金额/数量汇总时，要求先聚合明细或拒绝混合粒度查询，避免 join fan-out 使总额翻倍。库存量不得跨计量单位、物料或库区口径随意相加。
- 每个实体在参与 JOIN 前分别应用行列策略。LEFT JOIN 的受权右表使用预过滤派生表或等价 ON 约束，保留无可见子记录的主表；不能在最终 WHERE 添加右表条件将其变成 INNER JOIN。明细表通过所属主单据验证范围，不假定每张表都有 create_dept / del_flag。
- 新增 ReportDatasetResolver，支持 CODE_PROVIDER 与 CATALOG_QUERY 两类固定数据集版本。rpt_query_definition / rpt_query_version 保存查询草稿和不可变发布；rpt_dataset_version 关联 queryVersionId、catalogVersion 与 descriptor。定义/查询/目录版本及权限指纹均进入运行固定绑定。
- 查询目录执行采用独立 SELECT 权限账户和配置在服务器的只读数据源。只读事务、连接 readOnly 和超时是补充控制；不能替代实际数据库账户权限与系统级目录限制。
- 不把现有 AI SqlSafetyValidator 或 MyBatis 租户拦截器当作目录执行的通用权限重写器。第一版自研受限 AST；复杂关系优化有实测需求后再验证 Calcite 或现有解析库，保留生成 SQL 的攻击语料测试。

验收：双租户/双部门/列权限/无权限右表 LEFT JOIN/空数据/聚合粒度/绑定参数/禁止语法/超时与取消；读账户不能写库；旧查询版本保持运行口径；任一参与实体撤权使运行和后续下载被拒绝。单库明确一致性等级，不把未来 ERP/MES 混合取数称为强一致。

### E3：交叉表与受控钻取

- E3 新增报表类型时引入 DSL v2 与对应 engine 执行器，先完整支持交叉表；E4 在同一 schema 的明确能力集上继续扩展，语义变化仍发布新 engine version。新增 PivotDefinition / PivotPlanner / AggregationExecutor，先采用 SNAPSHOT，行维度最多 3 个、列维度最多 2 个、指标最多 5 个，输出最多 20,000 个单元格、200 个动态列；参数为建议初始限额，基准后调整，不通过截断伪造总计。
- 支持 SUM、COUNT、MIN、MAX、AVG，小计/总计、空维度、稳定排序、Top N 与显式“其他”桶。AVG 按 sum / count 重算总计，不对分组平均值再求简单平均；COUNT 是记录数或非空值需在定义中声明。
- 聚合权限覆盖分组字段、指标和 drill filters；即使敏感列只出现在排序/筛选/HAVING 中也要检查。涉及金额/数量的维度规则延用现有 DatasetField 聚合约束。
- 一份标准 PivotResult / RenderPlan 供浏览器、PDF 和样式 XLSX 使用。超过纸张可用宽度时要求用户切换方向或显式定义分页列段；没有横向分页能力前明确拒绝 PDF，不静默缩小/截断。
- 钻取只支持固定目标报表/业务入口和类型化参数映射，服务器重新鉴权。默认基于同一快照生成明细；用户选择 LIVE 时明确显示新的读取时间。禁止模板配置任意跳转 URL。

验收：稀疏矩阵、空维度、多币种/单位隔离、AVG 总计、Top N 其他桶、列上限、跨页重复表头、三格式数字一致；钻取无越权、不暴露隐藏字段，固定快照路径不重新取数。

### E4：业务单据与打印增强

- 通过 E3 已引入的 DSL v2 / RenderPlan v2 及新 engine version 增加文本/表格区域、受控图片、QR / Code128、分组标题/小计、纸张方向、重复页眉/页脚、连续页码及签字栏。第一批仍限制一个增长明细区；任意多主从/嵌套另列 P2。
- 图片通过私有 AssetService 上传、解码、大小与像素限额、checksum 和授权读取；不从模板 JSON 内远程抓 URL。发布绑定 asset version，运行计划封装图片/条码产物，保护重启和导出的一致性。
- 字体、图片及条码在服务器确定。SVG/脚本不直接进入业务 PDF。二维码只承载批准业务编码或受控路径，不嵌入登录 Token、账户密钥或整份业务明细。
- PDF 为打印交付基准，提供浏览器预览/打印和经鉴权文件；批量单据以批次记录固定单据集合、逐单据权限和每个 runId。没有独立客户端及设备验证前不承诺静默打印。
- 条码必须做打印后实际扫码验收，包含错误字符、长度、留白、纸张/DPI 和汉字内容。电子签章若接入现有 ESignatureService，使用其授权、留痕和业务签署流程，不能把一张印章图片作为签署证明。

验收：旧 v1 模板不变化；新图片/条码/分组样本的坐标、分页、预览/PDF/样式 XLSX 内容一致；字体/图片缺失或不兼容明确失败；批量中一份撤权不交付该份，失败和已成功单据不被全批重跑覆盖。

### E5：仪表盘与图表

- 使用现有 ECharts 基础库，自有 DashboardDefinition / WidgetRegistry，仅开放指标卡、柱/折线/饼图、明细表和交叉表。组件不能执行 JS formatter、表达式脚本或任意 HTML；后台发布 schema 与前端一致。
- 每组件绑定固定 report / dataset version，参数联动使用类型化映射。不同数据源显示各自 dataTime / consistency，页面不伪装为跨库同一快照。
- 服务器计算指标和同比/环比口径；原始 ID/DECIMAL 保留精确字符串。图表坐标可用服务器生成的受控数值投影，tooltip / 下载仍使用精确值，浏览器不重新计算业务总额。
- 提供编辑、发布、个人收藏、移动端布局、刷新/暂停和错误状态。建议默认不快于 30 秒刷新，隐藏页面暂停；每用户/租户与组件数限流。第一版不共享跨用户数据缓存。
- 若增加缓存，键包含 tenant、actor、权限范围与策略版本、数据契约版本、规范化参数及有效期；命中前仍重新鉴权。权限变化清理或拒绝旧缓存，不能用“同角色”代替相同数据范围。
- 首阶段验收在线交互。图表 PDF 需独立服务器渲染探针，并固定图表资产、字体和生成版本；支持该能力后再增加导出入口，浏览器截图不作为精确报表导出。

验收：参数联动一致、隐藏页不轮询、同角色不同部门互不共享、撤权后刷新/导出拒绝、图表与精确表格值对应，异常组件不影响其余组件，并通过真实组件交互测试。

### E6：共享存储、容量与集群运行

- 先补 ReportArtifactStore 的流式上传/读取、长度与 checksum、幂等删除、私有本地 staging，以及需要 Path 的 ZIP/PDF 库的受限 materialize 生命周期。逻辑 storeId 为存储命名空间，不绑定主机名。
- 在独立私有 bucket / namespace 上实现共享对象存储，保留 tenant 路径和认证服务代理下载。现有通用 OSS 附件可能有公开地址配置，需要验证私有实现，不能直接复用其外链交付。
- 每次有效注册前文件都可能留下孤儿，采用租约/年龄/完整引用校验与有界游标；元数据仍按确认删除后清理引用。对象存储上传未完成、临时 staging 和分块快照都纳入恢复。
- 增加全局/租户硬配额、任务优先级、公平调度、快照块索引和分页定位；不立即突破 100,000 行的当前限制，先通过实测决定下一档。文件页读取不随 offset 重复从头扫描的优化也须精度/排序回归。
- 字体从当前每运行副本可演进到按 checksum 的私有受控共享资源；必须有引用计数/使用租约或足够保留窗口、完整性验证和异常清理，不能因去重破坏运行固定字体。
- 双节点测试：节点 A 接任务、节点 B 读取和下载，kill/restart 后新 attempt 接管，旧 attempt 无法提交；网络失败、对象删除失败、过期/撤权和跨租户全局限额同时覆盖。

验收：两个节点相同 storageId 能读取同一注册对象；没有公开外链；严格配额结果可以复核；断点和清理均有可重试记录；峰值堆内存、RSS、临时磁盘、对象数和清理周期实测记录完整。

### E7：定时订阅与站内交付

- 复用 SnailJob 触发器，但 schedule / execution / delivery 各有持久记录，幂等键为 tenant + subscription + scheduledInstant + recipient。cron、时区、停用、补跑窗口和夏令时语义明确；手动运行与定时运行可区分。
- 订阅绑定固定发布版本与参数规则，升级版本需显式操作。每接收人以自身当前权限运行/交付；第一版按接收人分别生成，避免把生成者的宽范围文件发送给低权限接收人。
- 定时触发、执行、上传和领取时均检查账户、角色、资源、业务及字段权限；异常线程显式传播不可变 tenant / actor，不依赖登录 ThreadLocal。
- 首版只在导出中心/现有站内通知中交付授权领取入口，通知仅含必要摘要。自动站内通知属于该功能将来需明确启用的行为；制定计划和测试不发送任何真实通知。
- 报表下线、账户禁用、权限撤销或资源过期使领取失效。失败可重试但保持同一计划版本和授权范围；审计保留触发/生成/发送/领取的分别结果。
- 邮件/IM 外部分发、长期保留和外部接收人另行明确业务授权；公开分享与嵌入列入独立规格。

验收：重复调度只产生一次有效交付；两租户同名任务不冲突；接收人降权不获得旧范围文件；下线与过期阻断领取；retry 与取消不重复通知；时区和断点补跑有真实测试。

## 7. 后续独立范围

- 外部分享/嵌入：短期、可撤销、限定资源/参数/次数/接收主体的访问能力；不复用登录 token。需业务授权和分享接收人模型后单独规划。
- 复杂单据：多个增长区域、嵌套主从、横向分页、任意动态合并、批次套打。按实际样本逐类扩展，不承诺 Excel 全部语义。
- 跨库分析：明确业务快照/水位和 BEST_EFFORT 标识，不能直接在 JVM 拼两份当作同一时点账务报表。
- AI 设计辅助：模型提出模板/字段/公式建议，仍经过同一 schema、精确计算、字段权限和发布校验；模型不生成事实 KPI、不直接执行 SQL 或业务写操作。
- 平台独立服务化：只有容量/发布隔离数据证明需要时再拆独立服务，保持 common-report 边界；当前继续模块化单体。
