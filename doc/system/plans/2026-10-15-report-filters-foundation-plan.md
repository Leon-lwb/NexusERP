# 报表业务筛选与基础内容扩展实施计划

日期：2026-10-15；分支：codex/report-module-plan；基线：8a9d577f。用户已授权本轮代码开发；数据库写入仍由有权限用户显式触发正常基础报表初始化，不执行目标环境SQL脚本，不自动提交或推送。

**目标：** 将报表原始ID输入改善为按编码/名称/完整ID查找并回显业务对象，提供17类可按当前权限生成的基础模板，完善明细、中文状态和有口径的汇总。

**方案：** 复用现有Lookup SPI并增加按值解析接口，以固定数据集版本和参数定位代码规则。共用安全JDBC候选底座，ERP/MES各自绑定数据源，所有查询保留租户、删除标志、组织范围、参数绑定和查询后权限复核。新增数据集使用独立代码和版本1，保留现有六类契约及已发布报表。模板只增量创建，不覆盖用户已修改、下线或归档的同编码定义。

## 建设内容

| 能力 | 实施内容 |
| --- | --- |
| 业务筛选 | 搜索名称、编码或完整ID；选中项按ID回显；分页去重；查询失败重试；旧请求和旧定时器失效；ID全程字符串；数据集样例、草稿预览和正式运行共用 |
| ERP新增数据集 | 物料台账、客户台账、供应商台账、库存收发流水、销售订单明细、采购订单到货明细，共6类；仅投影代码固定字段，不含联系方式或银行账户 |
| MES新增数据集 | 工单执行跟踪、来料检验台账，共2类；取数走mes，ERP候选由各自授权的ERP Lookup提供，禁止跨库SQL联表 |
| 业务选择器 | 保留已有仓库、物料编码、客户、供应商、采购订单、送货单选择器；补来料检验、工单及新增目录的ID绑定；无已授权绑定时保留明确的完整ID输入 |
| 模板扩充 | 原6类 + 新8类 + 库存可用量、销售执行与分币种合计、采购执行与分币种合计3类 = 17类；具体数量受业务和字段权限限制 |
| 内容优化 | 推荐列宽、日期默认提示、单据规格与单位/币种、签收/检验字段；新台账提供中文状态；库存可用量在服务端计算；金额不跨币种、数量不跨物料/单位相加 |
| 兼容性 | 原provider版本不改、schema1/engine1继续可用；已发布版本不改、草稿revision和资源ACL仍由已有流程约束；新接口不接受表名/SQL/身份 |

## 核心验收

输入完整雪花ID能搜索与回显正确名称，返回候选不能越租户、组织或字段权限；迟到结果不能替换新选择。外部/已删除/失效对象不会被伪造成可见候选，回显失败不悄悄清空原参数。模板输出来自真实物理字段，未定义的业务指标不自行编造；大数、币种和单位保留精确口径。新模板的生成与已存在模板并存，反复初始化不覆盖用户版本。全部新增Java/TS/Vue具名契约和函数使用中文Javadoc/JSDoc。
