## 四、必须先看的三件事（影响后续 Task）

### 4.1 SMS 认证已从 P1 移除

`/sms-code` 端点**已删除**，`SMS` 已从 `SignAuthMethod.SUPPORTED` 移除。
原因：短信发送 API 存在（sms4j），但**手机号取不到** —— `LoginUser` 无 phone 字段，而 `sys_user` 属 `ruoyi-system`，
common 模块不能反向依赖。
**P1 实际支持：`LOGIN_ONLY` + `PASSWORD`。** `SmsSignCredentialChecker` 与其测试保留（占 6 个测试）。
→ **Task 14 的签署弹窗不得出现短信选项。**
（若日后要恢复：把发码端点放到 `ruoyi-system`，或给 `LoginUser` 加 phone。）

### 4.2 印章"防滥用"在 P1 只完成了一半 ⚠️

- `SealVo` / `AvailableSealVo` **不含 `sealOssId`** ✅（原图无直接 OSS URL 暴露）
- 但 **`preview_oss_id` 在整个 P1 没有任何写入点**（grep `setPreviewOssId` → 0 处）。
  水印预览图生成在 spec 里被划到 **P2**。
- 结果：`/system/sign/seal/{id}/preview` 走的**服务端回退**，返回的是**印章原图的 ossId**。
  即：原图仍可经"权限校验过的接口"取到，只是没有直接 URL。

**架构阻塞（重要）**：`ruoyi-common-sign` **无法读写 OSS** —— `ISysOssService`/`SysOssVo`/`OssFactory` 都在
`ruoyi-modules/ruoyi-system`，而 `ruoyi-system` 已依赖 `ruoyi-common-sign`，common→system 会成环。
所以**水印+降采样不能放在 sign 模块内**。可选路径：
(a) 前端上传时用 canvas 生成低清水印图，作为 `previewOssId` 一并提交（上传者本就持有原图）；
(b) 在 OSS 可达的模块（如 `ruoyi-system`）用 SPI/事件触发。

→ **Task 17 需把 spec 的 P1/P2 边界写清楚，并把 task17 验收表第 9 项措辞改准确**（现措辞是"无任何接口返回 `sealOssId`"，
这个成立；但不能宣称"原图不外泄"）。

### 4.3 菜单权限未授给任何角色

Task 2 只种了 `sys_menu`，**没有 `sys_role_menu`**。除超管外看不到「电子签章」菜单。
仓库既有先例（09-14 条目）会给角色 1/3 授权。**这是一项治理决策 —— 谁能用公司章 —— 建议由你确认后再补，不要由 Agent 猜角色 ID。**
