# 导航栏与主题设置交互优化规格

日期：2026-10-21。开发仓库：WZQAQA/nexus-erp，分支 codex/wzq-dev，基线 2537fadb。

用户已确认统一顶部工具栏和主题/布局设置，允许针对不合理的图标创建 SVG。实际开发目录为 D:/workspace/wzq。

## 目标与范围

1. 顶部导航统一使用可通过键盘操作、有可访问名称和清晰焦点的按钮。保持 50px 导航栏高度，保留搜索、AI、通知、租户切换、全屏、组件尺寸、文档、仓库与个人菜单。
2. 低频操作收进更多菜单；窄屏保留搜索、通知、主题入口，并从更多菜单访问 AI、租户与其他工具。面包屑与顶部菜单使用剩余空间，头像与按钮垂直对齐。
3. 主题和布局统一到一个自适应抽屉，按外观、布局和偏好组织；两个原有入口打开同一组件的对应分组。保留浅色、深色、高对比度、品牌色、导航、密度、页签、组件尺寸、动态标题等现有能力。
4. 直接绑定 Pinia 中的当前值；设置即时生效并自动保存到当前浏览器。恢复默认通过状态更新完成，不刷新页面；取消恢复不改变状态。
5. 仅在当前导航范围新增线性 SVG 资源，统一视框与描边；不改变全站已有图标。

## 实现边界

沿用 theme-config 和 dynamic-title 的存储键，租户接口、登录退出、通知跳转、头像 URL 安全校验及 AI 抽屉协议保持兼容。不引入后端、数据库或外部服务修改。移动端顶部导航通过现有侧栏访问菜单。

## 验收

- 实际组件运行测试覆盖颜色外部更新同步、布局分组入口、键盘按钮、移动端入口以及字符串超级管理员 ID。
- 定向 ESLint/Prettier、前端类型检查、单元测试和生产构建。
- 浏览器核对桌面及 375px 窄屏、三种主题、抽屉切换/关闭/恢复默认及导航空间。
- 测试采用合成用户和通知，不操作真实业务数据。记录实际结果，不将本地验证视为部署验收。
