# NexusERP 1.1 正式发布！MES + IoT 双引擎加持，从"管业务"到"管车间"

**NexusERP 1.1 今天正式发布了。**

1.0 发布之后，收到了不少朋友的试用反馈，其中最集中的声音就是："业务流程这块已经够用了，但车间现场的管理和设备数据这块，什么时候能补上？"

说实话，这也是我们自己最想做的事。ERP 管的是"账"和"流程"，但对制造企业来说，真正创造价值的事情发生在车间里——工单怎么流转、质量怎么把控、设备状态怎么样、环境数据有没有异常……这些如果管不住，ERP 里的数据再漂亮也只是"事后诸葛亮"。

所以 1.1 这个版本，我们做了两件大事：**一套完整的 MES（制造执行系统）** 和 **一个 IoT（物联网）设备接入平台**。更重要的是，这两者不是孤立的——它们和 1.0 的 ERP 模块深度打通，形成了从"接单 → 排产 → 执行 → 监控 → 追溯"的完整闭环。

---

## 先回顾一下 1.0：一套能用的 ERP

如果你是第一次听说 NexusERP，这里快速回顾一下 1.0 的核心能力：

NexusERP 1.0 覆盖了制造业和贸易型企业最核心的六大业务模块：**基础数据管理**（物料主数据、多级BOM、客户/供应商档案、计量单位体系）、**销售管理**（报价 → 订单 → 退货全流程闭环）、**采购管理**（低库存自动生成采购申请、收货差异报表、供应商评估）、**生产管理**（生产计划 → BOM展开 → 工单 → 委外/返工/报工）、**仓储管理**（三级库位、盘点过账、批次/序列号追溯、库存台账校验、安全库存预警），以及 **排产调度**（班次/班组/排班/打卡/考勤）。

此外还集成了 Flowable 7.0 工作流引擎、AI 智能对话助手（支持 DeepSeek/通义千问/智谱/Ollama）、积木报表、即时通讯、支付管理、多租户架构等基础能力。

1.0 解决的是"企业日常经营流程数字化"的问题。而 1.1，我们要把触角伸到车间现场。

## 1.1 新增了什么？两大重磅模块

### 一、MES 制造执行系统：让车间管理"看得见、管得住、追得溯"

MES 是 1.1 最重要的新增模块，包含 6 个子系统、20+ 张数据库表、25+ 个前端页面，覆盖了车间执行层面的核心场景。

#### 1. 生产工单与流转卡

1.0 的生产管理解决了"从计划到工单"的问题，但工单下达之后在车间怎么流转、每道工序做到哪了、谁做的、结果怎么样——这些在 1.0 里是管不到的。

1.1 新增了完整的工单执行管理：工单下达后，系统自动生成**流转卡**（Flow Card），每道工序对应一张流转卡，记录工序名称、计划数量、完工数量、合格/不合格数量、操作人、开始和结束时间。工人每完成一道工序，在流转卡上"报工"，数据实时更新。管理者可以随时查看一张工单当前的工序进度、各工序的合格率，以及是否存在瓶颈工序。

同时，工单支持**条码扫描**操作，工人扫一下工单条码就能开始/结束工序，不用在电脑前手动操作，这在车间环境下实用得多。

此外，MES 模块还引入了独立的**派工调度**功能，支持将工单拆分派工到具体的工位和操作人员，以及 MES 层面的**工艺路线**和**制造物料**管理——在 ERP 主数据的基础上，定义车间实际执行时的工序路线和用料标准，让"计划"和"执行"之间的衔接更加顺畅。

#### 2. 安灯报警（Andon）

安灯是精益生产里的经典概念——生产线上出了问题，工人拉一下"绳子"，所有人立刻知道哪里出了问题。NexusERP 把这个概念数字化了。

工人可以通过安灯终端（或移动端）快速发起报警，选择报警类型（设备故障、质量异常、物料短缺、安全隐患等），系统自动通知相关人员。安灯记录包含报警时间、响应时间、处理时间、解决方案，形成完整的问题处理闭环。管理层可以通过安灯统计报表，看到哪条产线问题最多、哪种类型的报警最频繁、平均响应时长是多少——这些往往是产线改善最有价值的数据。

更关键的是，安灯不仅可以手动触发，**IoT 平台的设备告警也能自动创建安灯记录**（后面会详细说）。

#### 3. SN 追溯与 MBOM

对离散制造来说，序列号（SN）追溯几乎是刚需。1.0 的仓储模块已经有了批次管理和基础追溯能力，但粒度和深度还不够。

1.1 的 MES 引入了 **SN（序列号）管理**：每个成品或关键零部件都可以分配唯一的序列号，从原材料入库、生产装配、质量检验到成品出库，每一个环节都关联到具体的 SN。支持**正向追溯**（从原材料批次查到用了这个批次的所有成品）和**反向追溯**（从一个成品 SN 查到它用了哪些原材料批次、经过了哪些工序、每道工序的操作人和检验结果）。

同时引入了 **MBOM（制造物料清单）** 的概念。和 ERP 里的设计 BOM 不同，MBOM 反映的是"车间实际怎么装配的"——它可以在设计 BOM 的基础上调整工艺路线、替代物料、工序用量等，更贴近生产实际。

#### 4. 质量管理：IQC → IPQC → OQC 三道关

1.0 里没有独立的质量管理模块，1.1 补齐了这块短板，覆盖从原材料到成品的三个检验环节：

**IQC（来料检验）**：采购入库时自动触发来料检验单，检验员按照预设的检验标准（检验项目、抽样方案、合格标准）进行检验。检验结果支持合格入库、不合格退货、让步接收三种处理方式。不合格品自动关联到供应商评估数据，形成质量反馈闭环。

**IPQC（过程检验）**：在生产过程中设置关键检验点，工人在工序流转时触发过程检验。支持首件检验、巡检、末件检验等模式。检验不合格时可以直接触发安灯报警，防止不良品流入下道工序。

**OQC（出货检验）**：成品出库前的最终检验，按照出货检验标准抽检或全检。检验通过后才允许出库，从流程上杜绝不合格品流出。

三个环节都有独立的检验记录，支持按物料、供应商、时间段等维度查询和统计分析。

#### 5. 设备管理

设备是车间的核心资产，1.1 新增了完整的设备台账和维护管理：

设备台账记录每台设备的基本信息（型号、厂家、购入日期、所属车间/工位）、运行状态、以及**关联的 IoT 设备**（后面会讲）。维护管理方面，支持三种模式：**计划性保养**（按周期自动生成保养工单）、**故障维修**（关联安灯报警或手动创建维修工单）、**维修记录**（故障描述、维修措施、更换零件、维修工时，形成设备维修档案）。

设备详情页可以直观看到这台设备的保养计划、历史维修记录、关联的 IoT 传感器数据——把设备管理和物联网数据真正串在了一起。

#### 6. 数据采集与 SPC 统计过程控制

这两个功能放在一起说，因为它们解决的是同一个问题的两面：数据采集解决的是"数据从哪来"，SPC 解决的是"数据怎么用"。

**数据采集**支持两种模式：手动录入（工人在采集点手动填写数据）和自动采集（通过 IoT 平台自动获取传感器数据）。每个采集点可以配置采集频率、数据类型、上下限等参数，采集到的数据自动关联到工单、工序和设备。

**SPC（统计过程控制）** 是质量管理的进阶工具。系统根据采集到的数据自动计算控制图的 UCL（上控制限）、CL（中心线）、LCL（下控制限），实时监测数据是否超出控制限。一旦检测到 OOC（失控）信号，自动标红预警。控制图采用 ECharts 渲染，支持实时刷新，车间看板和管理者都能直观看到过程是否受控。

### 二、IoT 物联网平台：让设备"开口说话"

如果说 MES 解决的是"车间管理怎么做"，那 IoT 解决的就是"设备数据怎么来"。1.1 的 IoT 平台是一个完整的设备接入和数据采集平台，从设备注册到数据展示形成了一条完整的链路。

#### 1. 产品与设备管理

IoT 平台采用"产品 → 设备"的两层模型。**产品**是设备模板，定义了一类设备的通用属性（设备类型、通信协议等）；**设备**是产品下的具体实例，每台设备都有独立的身份标识和接入凭证。

设备创建时系统自动生成 **deviceSecret**（设备密钥），设备用 ClientID（设备编码）+ 密钥进行 MQTT 连接认证。支持直连设备和网关两种类型，通信协议预设了 MQTT、OPC-UA、Modbus、HTTP 四种（当前版本完整实现了 MQTT，其余协议预留了扩展接口）。

#### 2. 内置 MQTT Broker

这是 IoT 平台最核心的部分。我们没有选择依赖外部消息中间件，而是**在应用内嵌入了一个 Moquette MQTT Broker**——部署 NexusERP 的同时就自带了 MQTT 接入能力，不需要额外安装和配置任何中间件。

Broker 支持完整的设备认证和权限控制：设备连接时用 ClientID + 密钥认证，采用安全比较方式（不论密钥是否匹配，比较操作耗时相同，防止攻击者通过响应时间差异猜测密钥）；Topic 按 `iot/{租户ID}/{设备编码}/{业务类型}/{操作}` 格式组织，内置多租户隔离——设备只能发布和订阅自己租户的 Topic，跨租户访问被严格禁止。

设备上线、离线、异常断开都有完整的状态管理。设备支持 MQTT 遗嘱消息（Last Will）机制——设备异常断开时，Broker 自动向指定 Topic 推送遗嘱消息，订阅方可以即时感知设备离线，不会因为设备"悄悄掉线"而失去感知。

#### 3. 数据管道：MQTT → Redis Stream → 数据库

设备上报的数据经过一条精心设计的管道流入系统：

设备通过 MQTT 上报属性数据 → 消息写入 **Redis Stream**（高性能消息队列）→ 消费线程批量消费 → 批量写入 MySQL → 更新 Redis 最新值缓存 → 触发告警检查。

这条管道有几个值得注意的设计。消费端采用**消费组模式**，支持消息重试和 ACK 确认。当批量写入失败时，系统自动降级为逐条写入——这样即使某条数据格式异常，也不会阻塞整批数据的处理，我们称之为"毒消息隔离"。每条消息最多重试 3 次，超过后自动跳过并记录错误日志。这种设计在保证数据可靠性的同时，也扛得住车间场景下的高频上报。

#### 4. 告警系统

设备数据入库后，系统自动进行阈值检查。当某个属性值超过预设阈值（比如温度过高、振动异常），立即触发告警流程：

首先做**频率限制**——同一设备同一类型的告警 60 秒内最多推送一次，防止告警风暴。然后**自动创建 MES 安灯记录**——IoT 告警直接转化为车间安灯事件，相关人员第一时间收到通知。最后通过 **SSE（Server-Sent Events）** 将告警实时推送给同租户下的所有在线用户。

这条"IoT 告警 → 安灯创建 → 实时推送"的链路，是 MES 和 IoT 两个模块协同的核心纽带。

#### 5. 实时监控大屏

每台设备都有独立的实时监控页面，包含四个区域：

**设备状态卡片**：设备名称、在线/离线状态、基本信息一目了然。**最新数值卡片**：每个监测属性一个卡片，显示当前最新值（从 Redis 缓存读取，毫秒级更新）。**实时曲线图**：基于 ECharts 的滚动窗口图表，每 3 秒通过 SSE 推送新数据点，保持最近 60 个数据点的实时曲线。**历史趋势图**：加载最近 1 小时的完整历史数据，按属性分组展示趋势。

SSE 连接内置了断线重连机制（最多 5 次自动重连），并且做了优雅的资源清理——页面离开时自动关闭连接和释放图表实例。

#### 6. 运维保障

平台内置了三个定时任务来保障长期稳定运行：**心跳检测**（每 5 分钟扫描，超过 15 分钟无数据上报的设备自动标记为离线）、**数据清理**（自动清理 90 天前的历史数据，防止数据库无限膨胀）、**消息流修剪**（定时将 Redis Stream 裁剪在 10 万条以内，保证内存可控）。

## MES × IoT × ERP：三位一体，深度协同

1.1 最有价值的不是单独看 MES 或 IoT 有多强，而是它们和 1.0 的 ERP 真正形成了一个整体：

**ERP → MES**：销售订单驱动生产计划，生产计划生成工单，工单下达到 MES 执行。ERP 里的 BOM、物料、车间主数据通过 ERP Bridge 无缝共享给 MES，不用维护两套数据。

**MES → IoT**：MES 里的设备台账绑定 IoT 设备实例，设备实时数据自动流入 MES 的数据采集点，SPC 控制图直接消费 IoT 数据。IoT 告警自动触发 MES 安灯，车间问题从"发现"到"响应"的链路缩短到秒级。

**IoT → ERP**：设备运行数据、质量检验数据反向充实了 ERP 的生产记录，物料追溯从"出入库记录"延伸到了"生产过程中的每一步"。

举个具体场景：一个温度传感器检测到车间某台设备温度异常 → IoT 平台自动触发告警 → 告警推送给在线管理人员的同时，自动在 MES 创建一条安灯记录 → 维修人员在安灯终端看到报警并响应 → 维修完成后，设备恢复、告警解除、安灯关闭。整个过程数据自动流转，不需要人工在不同系统间搬运信息。

## 技术栈更新

1.1 在 1.0 的技术栈基础上增加了：

后端新增 **Moquette 0.17**（嵌入式 MQTT Broker）、**Redis Streams**（设备数据消息队列，基于 Redisson）、**SnailJob**（分布式定时任务调度）。IoT 模块采用独立数据源（dynamic-datasource），与 ERP 主库物理隔离，互不影响。

前端新增 **ECharts 6.0**（SPC 控制图、实时数据曲线、历史趋势图），以及全局 **SSE（Server-Sent Events）** 实时推送通道——不仅服务于 IoT 实时监控，还覆盖了系统通知、安灯事件、即时通讯等场景，让整个平台都具备了实时响应能力。

跨模块通信采用**契约模块**（ruoyi-common-iot）的方式——MES 和 IoT 通过接口契约解耦，各自独立演进，不形成硬依赖。

## 写在最后

1.0 的时候我们说，NexusERP 的目标是做一套中小企业"用得起、用得好、用得久"的 ERP 系统。1.1 的发布让这个目标更近了一步——从"管好账和流程"进化到了"管好车间和设备"。

MES + IoT 这两个模块的加入，让 NexusERP 不再只是一套"记录型"系统，而是开始具备了**感知和执行**的能力。设备在说话、数据在流动、异常在自动响应——这才是一个现代化制造管理系统该有的样子。

接下来的版本，我们会继续深化 MES 和 IoT 的能力，包括但不限于：更多通信协议的完整支持（OPC-UA、Modbus）、更灵活的质量管理配置、设备 OEE 分析报表、以及 AI 在预测性维护和质量分析场景的落地。

NexusERP 1.1，来了。欢迎试用，欢迎反馈。
