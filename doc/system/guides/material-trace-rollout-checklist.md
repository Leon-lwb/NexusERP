# 物料身份、条码与追溯切换及现场验收表

日期：2026-10-19。状态：代码与隔离环境验证见[验证记录](../plans/2026-10-19-material-trace-verification.md)；本表的真实环境和真机项目尚未执行。未填写的项不能视为通过。

## 发布包与环境记录

使用[接口契约](material-trace-api.md)、[分库结构](material-trace-schema.md)、[历史修复指南](material-trace-repair.md)和[库存身份转换](material-trace-stock-conversion.md)。四仓库的基线与变更清单随验证记录保存，服务端先提供兼容能力，再更新PC/PDA/Station/App。

由实际操作者填写环境代号、四端版本、ERP/MES数据库名和服务器UUID引用、租户及物料范围、备份编号和恢复验证编号、维护窗口、消息/离线任务水位。记录引用与摘要，不将连接口令、设备密钥、Token或真实业务备份加入仓库。

`nexus.trace.relay.enabled=false`是兼容发布默认值。普通数量生产保留旧路径；追踪物料不得退化为无身份数量过账。开启新协议时旧MES完工消费者停止产生业务效果；ERP独立生产的原流程仍保留。

## 切换顺序

1. 在有明确授权的目标环境执行只读预检，完整导出选定租户的白名单表及所有必需列，留存来源、水位和快照hash。按租户、物料、批次、仓储、计价组核对数量、预留、金额、正库存SN、消耗、完工清单和消息状态。
2. 用目标备份恢复的隔离环境演练分库增量及修复包。分别检查ERP/MES库基线、表结构和同名索引；主安装SQL不进入存量迁移步骤。实际环境DDL和修复SQL只由获得迁移授权的操作者执行。
3. 按证据分类：确定映射、歧义待核实、缺当前实物身份、缺历史关系。实物盘点确认在库SN后才生成库存身份转换计划；历史未知不从当前主数据、BOM或额度推算。
4. 进入选定范围停写窗口；停止接收该范围的新客户端作业，归集旧离线命令、在途单据及旧消息，记录水位。旧命令仍使用原commandId和原载荷，不能重新编号掩盖已提交结果。
5. 分库执行已审核的增量与修复包，逐项核对原值、版本和hash；冲突立即停止该项。先保持AUDIT，再复核库存身份、预留、计价组、批次、MES在制及冻结策略来源。
6. 部署兼容服务端与四端后启用新协议，核对outbox发送、inbox业务结果及ACK。确认旧通知和新outbox只有一条实际生效路径；积压、内容冲突及等待前序事件有明确处理记录。
7. 对已完成全部对账的物料通过业务策略入口切STRICT；保留其它物料AUDIT。策略版本和工单来源策略在业务明细中冻结；历史工单证据缺失保持待核实。
8. 完成下表现场验证，核对迁移后第一笔及一轮完整收发生产业务。恢复选定范围写入，并持续按原命令/事件检查待确认结果，不以HTTP成功或Broker ACK代替业务确认。

## 回退及补偿

没有新增业务时，使用原完整快照、迁移日志和原行hash生成恢复包；重复恢复不得重复记账。已有新业务时保留新的身份、事件和来源证明，生成增量补偿任务，以有来源的退货、冲销或调整单处理，不恢复覆盖旧库存快照。

应用回退只到能理解新数据的兼容版本。不能回到会覆盖多批次消耗、丢失逐SN明细或重新发送无身份完工数量的旧写入逻辑。原流水、已签署DHR和原标签任务保留；更正生成修订与关联记录。
