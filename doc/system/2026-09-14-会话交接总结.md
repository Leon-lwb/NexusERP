### 3. 物料分类「两个菜单不一致」（问题已闭环）

| 项 | 结论 |
|---|---|
| 现象 | 「物料管理」菜单左树 与「物料分类」菜单列表，展示的分类不是同一批 |
| 主因 | `BdMaterialCategoryServiceImpl.selectList()` 上有 **ERP 模块唯一的「列表级」缓存**，条件只在「无筛选」时命中。物料分类菜单不带参数→读 Redis（TTL 30 天）；物料管理菜单带 `status=1`→绕过缓存直查库。SQL 级重建不会触发 `@CacheEvict`，两条路径长期分叉（缓存里 53 条旧分类 vs 库里 116 条新分类） |
| 次因 | `BdMaterialVo.categoryName` **从未被回填**（只有 `fillBaseUomName`），物料侧看不到分类名 |
| 修复 | 去掉整表 `@Cacheable` 与 5 处 `@CacheEvict`；`BdMaterialServiceImpl` 新增 `fillRefNames()`/`fillCategoryName()`，分页/列表/详情/按分类批量查 4 个出口统一回填 |
| 验证 | 两菜单均返回同批分类、逐字段差异 0；`categoryName` 287/287 非空 |

### 4. 字典缓存陈旧导致 5 个 AI 字典返回乱码（已闭环）

同一个根因在字典上又中了一次：`ai_model_api_protocol` / `ai_model_capability` / `ai_model_currency` /
`ai_model_type` / `ai_provider_type` 这 5 个类型**接口返回乱码、数据库是正确的 UTF-8**
（库 `人民币`，缓存 `浜烘皯甯`）。单独 `HDEL` 该键后立刻恢复 → 证明是缓存旧值。
清掉 `sys_dict` 后 **228 个字典类型全量比对 0 不一致**。

> **运维铁律**：凡绕过应用直接改库（重建 / 导入 / 迁移 / 手工 SQL），完成后**必须清一次 Redis DB0 业务缓存**，
> 否则会出现「库里新、界面旧」，且因走不同代码路径而表现为「两个菜单不一致」。清缓存命令见报告 §10.6。

## 六、关键约束与坑（新会话务必先读）

### 数据安全
1. **3D 演示数据是唯一不可逆风险点**，硬指标：仓库 1 / 库区 4 / 库位 104 / 库存 55，改任何东西前先记下这组数
2. `DEMO-*` 物料只在 `wm_stock` 里、不在 `bd_material`，**是设计**，不要「顺手清理孤儿库存」
3. 任何绕过应用的 SQL 改库，**改完必须清 Redis DB0 业务缓存**（保留登录令牌），再跑
   `verify_cache_consistency.py`

### 架构
4. 多租户默认开启，写多租户表必须带 `tenant_id='000000'`
5. 雪花 ID 由全局 `JacksonConfig` 的 `BigNumberSerializer` 转字符串，**切勿**在局部 ObjectMapper 旁路
6. `@DS` 注解必须放在被实际调用的 Service 方法上，同类内部调用不触发 AOP 切换
7. AI 异步线程 / `@Async` / MQ 消费者写库需手动传播 `AiRequestContext`，否则 `tenant_id` 落 0
8. `SaTokenExceptionHandler` 必须保持 `@Order(HIGHEST_PRECEDENCE)`，否则认证异常被
   `GlobalExceptionHandler` 抢先捕获，返回 500 并泄漏 JWT 明文

### 分页
9. `MybatisPlusConfig` 设了 `setOverflow(true)`（"分页合理化"）：请求超出末页**不返回空页，而是回绕返回第 1 页**。
   这是上游既定行为，前端 `pagination` 会钳制页码；但**脚本按"空页即结束"遍历会重复取数**（本会话踩过）

### 成本
10. `bd_material.volume` 是 `decimal(18,9)`（本会话放宽），写入时保留 9 位小数
11. BOM 成本卷积口径：`Σ(叶子料 累计用量 × 标准成本) + Σ(工序 工时 × (人工费率×人数 + 机器费率×机台数))`；
    只有**无子 BOM 的 133 个叶子**（132 原材料 + 网关固件）参与物料成本，半成品标准成本不进产成品卷积
12. 成本标定只缩放**模板占位行**；产品专属料（机床床身 1250kg 铸铁等）与**高值外购总成**不缩放

### 编码
13. 自动编码接口 `system:autocode:get` / `system:autocode:preview` 的菜单权限是**按需授权**的，
    新建角色要在「角色管理」里勾这两个按钮，否则「自动生成编码」对普通角色不可用
14. 手工编了物料编码后要同步 `sys_auto_code_result`（rule_id=236），否则自动生成会从 1 开始撞号
