### 1.1 关键设计说明

- **ERP-PRD-01 只做"排产 → 消费排班"正向链路**（审计建议的最小可落地口径），不做"排产发布 → 生成班组排班草稿"反向联动（属功能开发，见 §2）。为避免未启用排班模块的环境排产全部归零：某车间在整个跨度内**完全没有排班数据**时不做任何收窄；一旦该车间有排班数据，其休息日（人力 0）产能即为 0。已知简化：不做工作站级人力分配，车间总人力工时作为车间内各工作站资源的产能上限。
- **ERP-DASH-01 未采用 `@Cacheable`**：Spring Cache 的 key 需显式带 tenantId，否则跨租户串数；改用服务内 `ConcurrentHashMap<tenantId, 快照>` + 5 分钟 TTL，等价且无跨租户风险（无 Redis 依赖、无多实例一致性问题——快照只是"最多旧 5 分钟"的计数）。
- **ERP-SCH-11 双保险**：DDL 唯一键是权威幂等，代码捕获重复键把 500 变成"请重试"；单号生成规则未改动（避免影响前端展示与对账习惯）。
- **ERP-CV-05 用 `default` 方法保留 8 参旧签名**：`ISchAttendanceService` 新增 9/10 参抽象方法，旧签名以 default 委托（accuracy=null），既有单测与外部调用零改动。

## 6. 风险与回滚说明

| 文件/脚本 | 风险 | 回滚 |
|---|---|---|
| `PrdScheduleServiceImpl.java` + `PrdLaborCapacity.java` | 排产结果会因人力约束变化（休息日/请假不再排产，多班次日产能可能高于 8h）。若某车间排班数据质量差（如未维护 `sch_team.workshop_id`），该车间会被"无排班数据"分支跳过 → 行为与修复前一致 | 删除 `applyLaborCapacity` 调用与新增字段即可 |
| `ErpDashboardServiceImpl.java` | 计数最多滞后 5 分钟；快照 key 含 tenantId，不跨租户。**若后续有人把 key 改成常量会跨租户串数**（注释已警示） | 还原 `fillCounts` 为直接 `selectCount` |
| `ErpDashboardController.java` | 非超管需被授权 `erp:dashboard:stats`，否则首页统计 403（预期收紧） | 还原为无权限码（恢复"任意登录可见经营数据"） |
