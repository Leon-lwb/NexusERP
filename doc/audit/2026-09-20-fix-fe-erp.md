### 1.2 FE-ERP-06 口径说明（先读后端再改）

- 后端 `PuPurchaseOrderServiceImpl.insertByBo/updateByBo`（`:151-192`）只做 `BeanUtils.copyProperties(bo, entity)` + `saveLines(...)`，**不重算**任何金额，也没有 `calcLine/calcHeader`；因此采购侧"后端口径"需以同模块既有实现为准：
  - `PuContractServiceImpl.java:454-460`：`lineAmount = unitPrice × quantity`（`setScale(4, HALF_UP)`）→ `taxAmount = lineAmount × taxRate` → `lineAmountExcludingTax = lineAmount - taxAmount`（`setScale(2, HALF_UP)`）。
  - `PuInvoiceServiceImpl.java:289-292`：`lineAmount = qty × unitPriceExcl`（HALF_UP 2 位）→ `lineTax = lineAmount × taxRate` → `lineTotal = lineAmount + lineTax`。
- 前端据此统一为（`PuPurchaseOrderLine` 字段语义：`lineAmount` 含税、`lineTaxAmount` 行税额、`lineAmountExcludingTax` 不含税、`taxRate` 为小数如 0.13）：
  ```
  lineAmount              = round2(数量 × 含税单价 × 汇率)
  lineTaxAmount           = round2(lineAmount × taxRate)
  lineAmountExcludingTax  = round2(lineAmount - lineTaxAmount)
  taxAmount(表头)          = round2(Σ lineTaxAmount)
  totalAmount(表头)        = round2(Σ lineAmount + freightAmount)
  ```
  `round2` 用 `Math.round(n*100 + Number.EPSILON)/100` 实现 HALF_UP，替换原先模板内联 `toFixed(2)`（`toFixed` 对二进制浮点的舍入时机与后端 `BigDecimal.HALF_UP` 不一致，是审计指出的分位差异来源）。
- 价税合计是否含运费：审计 FE-ERP-03 明确"若后端价税合计未含运费，需与后端确认口径后一并修正展示"。因后端根本不重算，前端即当前权威口径，本次定为**含运费**（`totalAmount = Σ lineAmount + freightAmount`），并已在 §7 后端需求中要求后端按同一公式落地，避免后续两侧再次分叉。
