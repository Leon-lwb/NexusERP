## 2. 未修复 / 部分修复项（含理由与建议）

### 2.1 门禁种子默认 `enabled='0'`（**需主代理确认的取舍**）

审计要求「补 `pro_step_check_rule` 的门禁种子」。脚本 §4 已为**所有实际在流转卡中出现过的工序**
补齐 `TOOLING_AVAILABLE`(sort 90) 与 `SOP_ACKNOWLEDGED`(sort 91) 两条规则，但 **`enabled='0'`（停用）**：

- `SOP_ACKNOWLEDGED` 若默认启用，**所有工位立即无法进站** —— 因为产生「已阅确认」签名所需的
  查看器确认按钮（前端需求 §7.1）尚未实现，前端无法产出 `sop_view_log` 行。
- `TOOLING_AVAILABLE` 若默认启用，所有未扫码传 `toolingId` 的进站会被拒绝（这正是 MES-TG-02 的
  修复目标），但前端进站流程当前不传 `toolingId`（前端需求 §7.2）。

**结论**：种子 + 代码都到位（代码侧已彻底去掉「不传参数静默放行」），启用时机交由业务按工序
逐条开启（脚本 §7 给了现成 UPDATE）。**若主代理认为应默认启用，请先确认前端两项需求已就绪**，
否则会直接阻断在产工单。

### 2.2 MES-SOP-05 的正文哈希采用「惰性计算 + 缓存」

审计建议在 `SopDocumentServiceImpl.doPublish` 发布时算哈希。本实现改为**查阅时解析**：
优先读 `sop_version.file_hash`，为空才读 OSS 现算并回写缓存。理由：① 不在发布关键路径上引入
OSS 读取（发布是事务内操作，远端 IO 失败会回滚发布）；② 保证「签名一定绑定当时看到的正文」，
而发布时计算只覆盖「发布后未被改动」的情形；③ 缓存回写使其只算一次。
**残留**：`file_hash` 在首次查阅前为 NULL，且「验签时重新读 OSS 比对 `doc_hash`」的校验入口未加
（`verifyDocument` 对逻辑签名仍按设计明确拒绝）。建议单开任务补一个「SOP 正文完整性核验」端点。

   Mockito 报 `Cannot instrument class ... because it or one of its supertypes could not be initialized`。
   → 改为在任务类上留一个包级可见的接缝方法（`tryThrottle(...)`），测试用 `spy` + `doReturn` 替换。

3. **LambdaWrapper 需要真实列缓存**：`Wrappers.lambdaUpdate()/lambdaQuery()` 在纯 Mock 单测下会抛
   `MybatisPlus can not find lambda cache for this entity`（且若该异常发生在 `try/catch` 内会被静默吞掉，
   表现为"某个 mapper 方法没被调用"）。→ 每个测试类加 `@BeforeAll` +
   `TableInfoHelper.initTableInfo(new MapperBuilderAssistant(new MybatisConfiguration(), ""), Xxx.class)`。
4. **`@MockitoSettings` 严格模式 + `@BeforeEach` 公共桩**：`setUp` 里的通用桩对不走该路径的用例是
   `UnnecessaryStubbing`（报 ERROR）。→ 用 `lenient().when(...)`。
