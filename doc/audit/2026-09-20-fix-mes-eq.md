### 2.2 MES-EQ-04（备件与 ERP 库存两套账）——只给方案，未动代码

本轮**没有**为 `eq_spare_part` 增加 `material_id`，理由：
① 该列属"跨模块账本统一"的第一步，只加列而不改 `EqSparePartServiceImpl` 的出入库链路，会引入一个**永远为空的映射列**，与审计"明确单一账本"的目标不符；
② 真正的落地需要 `wm` 出入库服务/MQ 通道 + `QueueConstants` 新通道 + ERP 侧消费者，属跨模块大改，本批次文件所有权不允许（`ruoyi-erp/**` 由其他代理独占）；
③ 用户决策是"大件出 MVP + 方案"。

**实施方案（供主代理排期）**：
1. **DDL**：`ALTER TABLE eq_spare_part ADD COLUMN material_id bigint NULL COMMENT 'ERP 物料ID(bd_material.material_id)'` + `INDEX idx_material_id`；存量按 `spare_code = material_code` 回填；
2. **主数据映射**：备件新增/编辑时经 `IMesErpBridgeService` 校验物料存在并回填 `material_id`；`lowStock` 增加"生成采购申请"动作（调 ERP `pu` 申请服务）；
3. **出入库发 MQ**：`EqSparePartServiceImpl.stockTransaction` 在事务 `afterCommit` 发 `QueueConstants.MES_SPARE_STOCK_QUEUE`（新增常量），消息体 `{tenantId, materialId, warehouseId, qty, txnType(IN/OUT/REPAIR_USE/RETURN), refType, refId, bizNo}`；ERP 侧新增消费者调用 `wm` 库存服务（幂等键 = `refType + refId + spareId + txnType`，DB 唯一约束优先）；
4. **切账本**：ERP 侧消费成功回写 `eq_spare_stock_log.erp_synced=1`，`current_stock` 改为 ERP 库存的**只读投影**（或直接由 ERP 查询接口提供），彻底消除两套账；
5. **对账任务**：日跑 `eq_spare_part.current_stock` vs ERP 库存差异报表。
> 风险提示：③ 前必须先保证 ERP 消费者幂等，否则重投会重复增减库存。

## 6. 风险与回滚说明

### 6.1 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **R1（高）未执行 DDL 即启动应用** | `EqEquipment` / `EqMaintenanceRecord` 实体已含新字段，`eq_equipment` / `eq_maintenance_record` 缺列时 MES 设备域**所有查询**报 `Unknown column` | 上线前必须执行 `script/sql/update/2026-09-20-mes-eq.sql` 第 1、2 节（或主脚本合并后的等价 DDL）；回滚即 `DROP COLUMN` |
| **R2 `planned_minutes` 口径变化** | 设备未配置 `planned_minutes_per_day` 时行为与旧版一致（480）；配置了非 480 的设备，其历史 OEE 与新的不可直接对比 | 上线后重跑 `POST /mes/eq/oee/aggregate` 回填；对比报表时注意口径切换日 |
| **R3 表现率/质量率由 1.0 变 null** | 前端若直接显示 `performance_rate/quality_rate` 会出现空白；`avgOee` 由"等于可用率"变为加权值 | 前端建议用 `performanceRateAvailable/qualityRateAvailable` 显示"占位"；`eq_oee_record.remark` 已写明原因。**前端改动不在本代理所有权内**，需前端代理同步 |
| **R4 `finishMaintenance` 误释放保养中设备** | 保养异常 → MAINTENANCE；若随后任一保养计划完成且结果正常、或任一点检合格，设备即回到 NORMAL（仍存在活跃报修时回 FAULT） | CAS 限定 `status='MAINTENANCE'`，不会影响 FAULT/SCRAPPED/NORMAL；业务上"点检合格/保养合格"即视为异常闭环，符合审计建议 |
| **R5 作废权限种子 id 冲突** | 增量脚本用 `menu_id=4127` + `INSERT IGNORE`；若该 id 已被占用则静默跳过 → 非超管调作废接口 403 | 主脚本合并时由主代理确认/分配空闲 id（§3.2b 已标注） |

| **R7 保养提醒频率变化** | P2/P1 级提醒比原来 24h 更频繁（12h/6h），安灯条数增加 | 分级阈值（7/30 天）与 TTL 都是类内常量，可按需调整 |
