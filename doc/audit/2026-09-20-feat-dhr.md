## 2. 未修复 / 部分修复项

1. **签名与状态流转不在同一个数据库事务里（物理上不可能）**：`dhr_record` 在 ry-mes，`es_signature` 在 ry-vue(master)。
   审计要求「同一事务」在跨库场景下无法成立。实现取「先签名（REQUIRES_NEW，master）→ 后单条 CAS 语句同时 SET
   状态/时间/签名ID（ry-mes 事务）」，使「已流转但未绑定签名」不可能出现；残余窗口为「有签名、无流转」
   （业务状态未污染、可重新发起，属安全失败方向，与 NCR 处置同一取舍）。详见 §6。
2. **无 DRAFT→编辑（updateByBo）端点**：契约只要求 build/rebuild，未定义通用编辑；DRAFT 期改动用 rebuild 覆盖。
3. **无归档后不可删除的 DB 级约束**：逻辑删除 + 服务层 DRAFT 校验；未加触发器（与仓库既有风格一致）。
4. **`sop_view_log` 签名摘要逐 sopId 回查（N+1，上限 50）**：`ESignatureService` 只提供按单 bizId 查询；
   若单工单查阅量 > 50 次，超出部分 `signature` 为 null（已打 WARN 语义：不阻断构建）。建议后续给
   `ESignatureService` 增加按 bizType + bizId 集合的批量接口。
5. **`qc_oqc`/`qc_iqc` 回退口径可能带出同物料的其他工单记录**：这两张表没有工单外键，只能按物料 + 时间窗，
   已在条目 `linkage` 中如实标注 `BY_MATERIAL_TIME`，未伪造关联。若审计要求更严，需给表加工单列（DDL 变更）。
6. **`dc_data_record`/`pro_sn`/QC/SN 分册有 `LIMIT` 上限**（500/200）：防止单工单快照无界膨胀；
   超大工单的批记录不完整，属已知取舍（快照哈希只覆盖落库内容，不声称覆盖全量）。
7. **前端菜单/页面不在本次范围**：`plus-ui` 由并行子代理完成，本报告不含前端改动。

## 6. 风险与回滚说明

### 6.1 数据源/事务边界（最高风险，已在代码中显式注释）

- `DhrRecordServiceImpl` 与 `DhrAggregateServiceImpl` 类级 `@DS("mes")`；`es_signature` 只在 master(ry-vue)。
- **写路径**：`signInNewTransaction`（REQUIRES_NEW）→ @DS 切面在「开事务、取连接」前把 master 压栈，
  签署落 ry-vue；**不得**改成 `sign()`（REQUIRED 会加入调用方 ry-mes 事务 → 事务内 @DS 不生效 →
  运行期 `Table 'ry-mes.es_signature' doesn't exist`；单测 mock 不会暴露）。
- **读路径**：`listSignatures` / `verify` **刻意不标 `@Transactional`**（有事务时 @DS 不切换，跨库读会读错库）；
  签名侧统一经 `DhrSignatureAccessor`（`@DS("master")` + REQUIRES_NEW）兜底。
- **残余窗口**：签名已提交、随后 CAS 影响 0 行 → 「有签名、无流转」。异常信息带当前实际状态，
  业务状态未被污染、可重新发起；`es_signature` 为 append-only 台账，多一条授权记录不构成合规风险。

### 6.2 其他风险

- **哈希口径锁定**：`sort_order` 与 `section_code` 拼接顺序一旦调整，历史批记录 `/verify` 将全部 FAIL。
  `DhrSectionCode` 的声明顺序即契约，已在类注释中标注「不得调整」。
- **`snapshot_hash` 覆盖范围 = 落库的分册内容**：分册条目受 `LIMIT` 约束（见 §2.6），
  批记录不声称覆盖工单全量明细。
- **多租户**：两表唯一键均含 `tenant_id`；原生 SQL 全部显式 `tenant_id = #{tenantId}`；
  聚合入口在 tenantId 为空时直接抛异常（不降级为跨租户读）。
- **签名台账跨库不可回滚**：回滚 DHR 表不会删除已写入的签名记录（append-only，合规上应保留）。

### 6.3 回滚

1. 代码：回退本批新增的 `ruoyi-modules/ruoyi-mes/src/main/java/com/nexus/mes/dhr/**`、
   两个测试类、`SignBizType` 的 3 个常量（删除常量即可，无引用残留）。
2. DDL：`DROP TABLE \`ry-mes\`.\`dhr_section\`; DROP TABLE \`ry-mes\`.\`dhr_record\`;`
3. DML：`DELETE FROM \`ry-vue\`.sys_menu WHERE menu_id BETWEEN 4370 AND 4380;`
   `DELETE FROM \`ry-vue\`.sys_dict_data WHERE dict_code BETWEEN 600254 AND 600258;`
   `DELETE FROM \`ry-vue\`.sys_dict_data WHERE dict_code BETWEEN 600264 AND 600273;`
   `DELETE FROM \`ry-vue\`.sys_dict_type WHERE dict_id IN (600212, 600213);`
4. 无需清 Redis；菜单/字典变更在用户重新登录或刷新路由后生效。
